# QQ Digest

本地 QQ 群消息采集、每日摘要、收藏与 Markdown 资料整理工具。

## Windows 试用版

普通用户从 [GitHub Releases](https://github.com/Deng919/qqchatbot/releases) 下载 Windows x64 安装包，无需安装 Python。安装时设置自己的登录密码，启动后按「首次设置」选择 QQ 账号、导入群聊，再填写自己的 DeepSeek API Key。

公开安装包仅支持 DeepSeek API，不包含 GPT 桥接、账号或密钥。也可跳过 AI，先使用本地采集和查找。AI 摘要与问答会把所选聊天片段发送到 DeepSeek。

[安装说明](docs/PUBLIC_BETA.md) · [问题反馈](https://github.com/Deng919/qqchatbot/issues)

以下为源码开发说明。

## 已实现功能

- 从本机 QQ NT 的解密数据库发现群聊并读取消息。
- 原消息优先显示本群群名片或昵称，不追加 QQ 号；名称来自本地资料缓存，缺失时显示号码或未知发送者。
- 首次回填最近 30 天，之后默认每 10 分钟自动刷新并增量采集。
- 按群分类生成自适应摘要：内容少时简洁，讨论丰富时自动扩展话题覆盖；默认使用 DeepSeek V4.1 Flash 的 OpenAI-compatible API。
- 将 Markdown 和 JSON 摘要写入 `reports/`。
- 历史摘要支持摘要仪表盘、按群阅读和管理报告；切换方式、刷新或展开群卡片时保留历史日期范围。
- 将资源与经验先放入候选审核，确认后写入 `knowledge/resources.md` 或 `knowledge/experiences.md`。
- Web UI 提供运行总览、群组配置、手动采集、摘要查看和候选审核。
- Web 服务内置独立的周期采集和每日摘要调度，也提供 CLI 和手动执行入口。
- 候选支持按状态、群、类型、日期和关键词筛选，并可查看历史状态与详情。
- AI、日报和 QQ Bot 通知均有有界重试；通知队列持久化在 SQLite 中。
- 异常处理支持单条忽略、一键忽略当前列表的待处理记录，以及在“已忽略”中恢复；新异常仍会显示，重试中的记录不受影响。
- 统一「收藏」入口保存原消息、摘要要点和资源，区分未读与已读；「整理的资料」展示长期保留的资源与经验，支持从原消息整理。
- 首次设置串联 QQ 数据检测、选群、导入、AI、自动计划和结果预览，刷新后可继续。
- 二手信息独立整理本地二手群：默认最近七天，支持跨群去重、价格来源、图片与完整转发记录、搜索收藏和按 QQ 号屏蔽。点击「更新交易信息」导入；未下载图片或无法展开的转发会保留未解析提示。
- 二手卡片和详情显示同条原消息配图，也可关联同一卖家连续发送的图片，后一类标注「连续消息配图」并提供「图片原消息」入口。关联要求同群、连续消息序号、同发送人及两分钟范围，来源不明或更接近另一段商品文字时不关联。本机缺图时自动从腾讯图片服务器补取原图、核对 MD5 并缓存，无需手动点开 QQ 图片；首次补图需 QQ 运行并登录，已缓存图片可离线复用。本机预览及自动补图与 AI 图片识别开关独立。
- 已接入二手信息的群不进入普通摘要侧栏、筛选、生成预览、手动／自动生成、重新生成及摘要统计；原始消息采集、群管理和已保存内容保留。
- 中文消息全文检索，支持发送人 QQ 号、消息类型、群与日期组合筛选，命中高亮和原文上下文。
- 归档问答：按群与日期提问，先预览消息片段，再发送给 DeepSeek，回答可打开原消息来源。默认关闭，在功能开关中开启。

查找页展开「筛选条件」可按发送人、消息类型查找聊天消息；摘要和知识沿用群与日期筛选。升级后的首次打开会为已有消息建立本地索引，索引随采集和数据库备份保存，无需调用 AI。SQLite 缺少 FTS5 时沿用原关键词查询。

QQ 数据库格式是私有实现，QQ 更新后可能需要同步调整解析器。刷新过程先复制主库与 WAL 的一致快照，再解密并校验当前采集路径使用的核心数据库，最后成组替换输出；失败时不会覆盖上一份可用数据。新版 QQ 存在全文库时，采集依赖 `group_info.db` 和 `group_msg_fts.db`，历史 `nt_msg.db` 的内部损坏会告警但不会阻止最新消息刷新。

若消息库因历史损坏未通过完整性校验，仍保留原有已验证主库；另外尝试以当前全文库的精确消息、群号和时间为锚点，将近三十天可读消息提取为独立、已校验的 `nt_msg_media.db` 附件索引。该来源明确标为不完整，不把损坏主库当作健康数据库发布；提取失败保留上一份可用索引。

自动补图仅用于已启用二手群的已授权图片来源；普通群图片查看不触发远程下载。临时下载凭据只读获取并保存在内存，原消息中只保存去除凭据的来源地址。图片只从固定腾讯图片域名获取，拒绝重定向并校验大小、格式、像素及原始 MD5；失败有冷却时间，缺失或过期来源保留不可用状态。本机版缓存位于 `D:\Cache\QQDigestDesktop\message-images`，按 QQ 账号隔离。

单击商品卡片、详情或原消息中的图片，可直接在当前页面查看放大原图；点空白、右上角关闭或按 Esc 返回，保留原来的详情和阅读位置。原图不可用时尝试已有本机预览。

## 安装

本机默认使用 Codex Python 环境：

```powershell
D:\CodexTools\python\Scripts\python.exe -m pip install -e ".[test]"
```

复制配置并生成登录密码：

```powershell
Copy-Item config/config.example.yaml config/config.yaml
D:\CodexTools\python\Scripts\qq-digest.exe hash-password "你的密码"
```

将密码散列写入 `security.web_password_hash`，再设置会话密钥。可以使用环境变量：

```powershell
$env:QQ_DIGEST_SESSION_SECRET="一段随机长字符串"
```

也可以把至少 32 个字符、无空白的随机密钥保存到项目外文件，并配置 `security.session_secret_file`。环境变量的优先级更高。

示例配置直接调用 DeepSeek V4.1 Flash 的兼容接口，模型 ID 为 `deepseek-flash`。JSON 输出模式用于降低摘要响应格式错误的概率。网页保存的 API Key 优先使用；未保存时沿用环境变量、`ai.api_key_file` 等原有来源。密钥不回显、不写日志；首次引导保存到数据目录的 `config/secrets/` 受限权限文件，该目录已从版本库排除，备份包含密钥。

```yaml
ai:
  provider_priority: [compatible]
  base_url: https://api.deepseek.com
  model: deepseek-flash
  json_mode: true
  api_key_env: DEEPSEEK_API_KEY
  ui_api_key_file: "D:/Dev/QQDigest/secrets/deepseek-api-key.txt"
```

若密钥保存在项目外的单行文本文件，可另设 `ai.api_key_file` 为该文件的绝对路径；不要把密钥写进配置或提交到 Git。

登录网页后在“AI 设置”输入并保存 DeepSeek Key，再按“测试连接”验证。保存本身不会发起网络请求；Key 写入上方的本机项目外路径，旧 Key 不会在网页回显。报告详情中的“问 DeepSeek”可针对该报告提问和追问：系统只取同群、同日期范围的已归档原始消息；上下文过长时按问题筛选消息及邻近记录。选中的聊天片段会发送到 DeepSeek，答案所列来源 ID 由后端核验。问答只在当前页面内存中保留，关闭对话框或刷新页面即清空；不会写入报告或数据库。

开发分支新增“查找 → 归档问答”：指定群、日期和问题，必要时填写关键词，核对预览后发送。未找到消息时不会调用 AI；来源仅来自本次发送片段。预览 15 分钟有效，修改问题或范围后须重新查找。本次更新加入独立登录会话标识，升级后须重新登录。此功能尚未进入公开版 0.2.0-beta.1 安装包。

「设置 → AI 连接 → API 用量」显示本月调用、成功／失败／未知结果、已知 token 和费用估算，可设置每月最多调用次数（0 为不限）。每次 HTTP 尝试单独计数，包括重试、图片识别和连接测试；超限不会发送请求，采集、本地文件提取和已有缓存仍可用。首次建立账本时固定统计时区，按自然月恢复额度；修改摘要时区不会重置计数，旧调用不补计。单价由用户按接口与模型填写，空值和服务方未返回的用量均记为未知；费用不是实际账单或人民币硬上限。设置、记录和发生时的费率随归档库备份。已进入 2026-10-08 Usage 本机版，公开安装包未更新。

按群读取附件：在「群聊」打开详情，勾选「读取图片」「读取文件」并保存，默认均关闭。开启后，已下载且来源校验通过的附件会自动参与新摘要和问答；图片通过 DeepSeek Flash 识别，文件在本地提取正文。「查看附件」显示读取结果、下载缺失和截断状态，并可重读、查看关联聊天上下文。关闭开关后，缓存内容不再加入新摘要或问答，历史报告保留。

支持 JPEG/PNG/GIF/WebP，以及 PDF、DOCX、XLSX、PPTX、TXT/MD/CSV/JSON/LOG。Office 读取正文、表格和幻灯片文字，不处理内嵌图片；PDF 最多前 10 页，无可用文字的页面交给识图。单附件最多 16 MiB、12,000 字符，每批最多 20 个；附件列表和重读覆盖最近 200 条附件消息。文件须先在 QQ 下载，图片从当前 QQ 账号的原图缓存按消息 MD5 核实；不下载远程链接。自定义 QQ 缓存位置目前需消息中含可用本地路径。此功能已进入 2026-10-07 Attachments 本机版，公开版 0.2.0-beta.1 安装包尚未更新。

如需使用本机 `codexID` ChatGPT bridge，可在确认包装器和账号池可用后，将 `chatgpt_bridge` 显式加入 `provider_priority`。

新生成的日报和范围摘要会为概览、话题、结论、资源、任务及未解决问题记录原消息引用。在「摘要」打开报告后，每条要点只有一个「关联的消息」入口，直接打开连续聊天上下文，不按 1、2、3 拆分。上下滑动可继续加载前后消息，仅有效关联高亮；上下提示可见区域外还有几条关联，点击提示可跳到最近一条；没有有效引用的内容标为「待核实」。旧报告不会自动推断来源，重新生成后才会得到新格式。生成及展示不再将引用截到三条；引用只允许指向该次实际提供给模型的消息，并在打开时再次校验群、报告日期和版本。旧报告当时被截断的引用须重新生成才能补充。

知识库 Markdown 文件可使用相对或绝对路径：

```yaml
knowledge:
  resource_path: knowledge/resources.md
  experience_path: knowledge/experiences.md
```

相对路径以项目数据目录为基准。Web 审核和 QQ Bot 指令会写入同一目标文件，并在归档库记录对应路径。

## 收藏与资料

侧栏「收藏」统一提供「已收藏」「整理的资料」两个视图；开启资料审核后另有「待确认」。原消息和摘要要点旁的「收藏」按钮保存当时的内容，支持关键词、类型和阅读状态筛选、查看来源、标为已读／未读和取消收藏。

收藏原消息后，可以在详情中选择「整理成资料」，补充标题、分类和说明，保存原文与来源。已有知识条目在「整理的资料」继续可读，并保留 Markdown 文件；旧 `/knowledge` 链接保留筛选和条目定位，转入收藏内的资料视图。资料页无需再次收藏同一条目。

收藏快照在来源消失或摘要改写后仍可读，重复收藏不改变阅读状态。「功能开关」中的「收藏原文」仅控制快照保存，关闭后仍可浏览整理的资料。备份继续包含已有数据。

话题跟踪和待办已从应用移除，相关入口、接口及待办到期提醒不可用；旧数据库中的历史记录仍保留，普通摘要中的讨论主题和明确安排可正常阅读。

## 配置真实 QQ 数据

桌面版打开后，从「设置 → 首次设置」进入：检测或填写已登录的 QQ 账号，读取数据、选择群聊，导入最近七天或自选日期，再设置 AI 和自动计划。已有解密库也可以填写完整路径；QQ 原数据库目录不能直接作为输出目录。读取当前 QQ 的缓存位于 `D:\Cache\QQDigestSources\<账号>`。

导入逐群记录结果，可刷新继续或重试失败群；重复导入去重，不推进自动同步游标。AI 可暂不配置，此时保留采集与查找，自动日报需连接测试通过。配置修改期间暂停自动采集、日报和巡检，点击「完成设置」后恢复所选计划。自动任务只在程序运行时执行。已有用户可以重访任一步，不会删除未选群或原消息。

数据源、接口地址、模型、密钥、采集间隔和每日时间均可在引导中保存。配置与引导状态随数据目录备份；外部修改配置文件后需重启，其他窗口保存后需重新载入。

CLI 仍支持在 `config/config.yaml` 中启用 NTQQ：

```yaml
ntqq:
  enabled: true
  qq_number: 你的QQ号
  db_dir: "D:/Cache/output/你的QQ号"
  timezone: Asia/Shanghai
```

先刷新数据库，再回填已选群：

```powershell
D:\CodexTools\python\Scripts\qq-digest.exe refresh --config-path config/config.yaml
D:\CodexTools\python\Scripts\qq-digest.exe backfill --config-path config/config.yaml --days 30
```

运行时群组配置以 `archive/archive.sqlite` 为准。`config.yaml` 的 `groups` 只做首次导入；在 Web UI 中添加、修改和删除的群组会直接持久化到归档库。
群组页可以分别配置重点关键词和首次采集天数。关键词会进入该群的摘要提示词，仅提高相关讨论的关注优先级，不会降低重点候选标准；首次采集天数只在该群尚无同步游标时生效。
群组页会显示逐群最近成功采集时间、自动同步游标和失败原因。点击“扫描本地群聊”后，可比较本地 QQ 源库和归档库的最近消息，提示可能漏采的群；“补采”会打开已选群和日期的采集页。先用“检查缺口”逐日统计所选范围内未归档的消息，再用“刷新并补采”一键刷新 QQ 数据库并去重补齐。检查不会修改归档或采集状态；补采旧日期不会回退自动同步游标。扫描页仅根据最新消息提示疑似缺口，历史范围的准确缺口以“检查缺口”结果为准。

每日摘要会在计划时间执行；失败时按配置间隔重试，程序启动后也会检查最近 3 天内失败或错过的日报，并补跑遗漏日期。补跑记录保存对应报告日期，不占用当天日报的重试次数；已有有效报告会复用。总览页分别显示消息同步和日报状态，日报失败不会被后续成功的消息同步掩盖。API Key 可在「设置 → AI 连接」中保存到程序专用的本机文件；读取时遇到短暂文件占用会重试。

## 启动

### Windows 桌面版

当前源码构建的桌面版在独立窗口中显示现有界面，启动时自动建立本机会话，直接进入摘要页。浏览器访问仍需密码登录；已发布的旧安装包需更新后才有此行为。开发环境可运行：

```powershell
D:\CodexTools\python\Scripts\python.exe -m pip install -e ".[desktop,desktop-build]"
D:\CodexTools\python\Scripts\python.exe -m qq_digest.desktop
```

构建可双击的 EXE：

```powershell
D:\CodexTools\python\Scripts\python.exe scripts/build_desktop.py
```

构建结果为 `D:\Apps\QQDigestDesktop\QQDigestDesktop.exe`，其旁边的 `_internal` 目录是运行所需依赖，应与 EXE 一起保留。`launcher.json` 保存现有 `config/config.yaml` 的路径；归档、报告和知识库仍位于原项目目录。默认构建缓存为 `D:\Cache\QQDigestDesktop`。如果要连接别处的数据，可修改 `launcher.json` 的 `config_path`。

桌面版“设置”可选择新的空文件夹，将消息数据库、报告、知识库及工作文件复制过去，并更新桌面启动配置；旧目录保留，重启后切换。摘要可按 Markdown、JSON 或两种格式导出，默认导出根目录为 `D:\Downloads\QQDigestReports`；每次导出建立独立子目录。开机自启开关写入当前 Windows 用户的启动项，初始为关闭。桌面程序运行期间，连接同一本地服务的浏览器也可以使用设置页。

在「设置 → 版本更新」查看已登记的本机版本。切换前先备份数据，再关闭并重新打开程序；确认窗口和服务启动成功后更新现有桌面入口及已启用的自启项。启动失败则恢复原版本，用户数据保留。切换只允许相同数据兼容性标识的程序包。

旧版本可先预览大小再清理；当前版本、回退版本、运行中的版本以及与数据路径重叠的目录会保留。构建脚本自动生成并登记 `release.json`，管理状态位于 `D:\Cache\QQDigestDesktop\updates`。未登记的旧目录不会自动删除。FirstUse 是首次回退基线，旧版没有「版本更新」页；回退后如需重新使用本次更新功能，可直接运行 `D:\Apps\QQDigestDesktop-2026-10-06-Updates\QQDigestDesktop.exe`。包含数据格式变更的后续发布必须调整清单兼容性标识，通过备份副本迁移预检后才能开放切换。

设置页还可打开当前存储目录和导出目录，并一键生成包含消息数据库、报告、知识库和配置的 ZIP 备份；备份默认放在 `D:\Downloads\QQDigestBackups`。备份会跳过可重建的 `work/snapshots` QQ 临时快照。新备份包含逐文件 SHA-256 清单，并在完成写入后才出现在最近备份列表。自动备份默认每周检查一次，可改为每天或关闭。文件夹选择窗口若被系统阻止，可在路径框中直接输入完整路径。

「设置 → 存储与导出」显示数据库、报告、知识文件、程序缓存、备份及日志占用和磁盘剩余空间。附件提取正文计入数据库，QQ 图片和文件原件不扫描。无法读取的部分显示统计不完整，文件大小合计不等同于磁盘实际占用。

自动清理默认开启：自动备份保留 30 天，并至少保留最新 3 份通过完整校验的备份；有本程序归属标记的缓存保留 7 天。可调整期限或关闭，程序运行时每小时检查，成功自动清理后至少间隔 24 小时；自动备份关闭时仍按清理策略执行。聊天记录、摘要、知识、手动及恢复／更新前安全备份、QQ 原件和无法确认归属的旧缓存会保留。手动清理需先查看预览，预览有效 10 分钟；策略或存储变化后需重新预览，执行时再次核对文件，显示实际释放量及跳过／失败项目。

恢复时在设置页选择 ZIP，先检查文件清单、ZIP、SQLite 数据库完整性和消息表结构，并预览消息、报告、知识条目数量，再指定一个空目录。程序会先将当前数据另存为安全备份，随后把选中的数据恢复到新目录并更新启动配置；旧数据保留，重启桌面程序后生效。旧版无清单的 ZIP 仍可恢复，但预览会提示无法验证逐文件哈希。若旧备份缺少原本保存在数据目录内的会话密钥，恢复时会在新目录生成密钥，原有网页登录状态随之失效。

“补看”页将各群已生成日报中的讨论、结论、资源、任务及未解决问题放在一个列表里，可按上次查看后、今天或最近七天筛选并逐条标记已读。首次打开时，“上次查看后”默认显示最近七天。新报告的「关联的消息」会列出全部有效关联，并可打开前后讨论；旧报告或无有效来源的条目会给出提示。补看只读取现有日报，不会重新调用 AI。若某天尚无日报，可在“摘要”页生成。

“待办”页汇集最近 30 天日报中有有效原消息引用的任务建议；先查看原消息，再填写负责人和准确的截止日期，确认后才成为正式待办，也可忽略。旧报告和无有效来源的任务不会自动进入建议。搜索结果中的聊天消息可直接点“加入待办”。正式待办支持编辑、完成、取消、重新打开，始终保留创建时的来源消息。今天到期和逾期数量显示在待办页及总览入口；到期通知可在提醒规则中配置。

顶部“功能开关”可开启默认关闭的“提醒规则”，随后从顶部“提醒”进入。支持关键词、新资源候选、待办到期和运行故障，按群选择程序内提醒、Windows 通知及免打扰时段。关键词为任一字面匹配；新建、重新启用或更改匹配条件后，历史消息、资源和故障不补发，当前已到期的未完成待办会提醒。仅改名称、时段或渠道不会跳过尚未检查的新增来源。预览只读本地数据、不发送通知；消息和资源预览最多检查最近 200 条来源、展示 20 条匹配示例。

程序运行期间每 60 秒检查，关闭程序或提醒功能后暂停。免打扰期间的新提醒持久排队，结束后再次检查待办和故障是否仍有效，再发布或投递；已有提醒仍可阅读。规则及已读状态随归档备份保存，重复扫描和重启不会重复通知，同群同链接资源按规则去重。Windows 每轮最多提交一条汇总通知；失败最多三次退避，结果未知时停止自动重发，可在投递记录中手动重试。系统接受请求不代表必定显示横幅，Windows 通知设置仍会影响显示。纯浏览器服务保留 Windows 排队，需使用桌面版投递；连接桌面后台的浏览器可查看其通知能力。

### 浏览器入口

Windows 下可双击项目根目录的 `start-web.cmd`。脚本检查服务状态，未启动时后台启动，并打开 `http://127.0.0.1:8765/`。也可手动运行：

```powershell
D:\CodexTools\python\Scripts\qq-digest.exe serve --config-path config/config.yaml
```

如果未配置 `security.session_secret_file`，启动前仍需设置 `QQ_DIGEST_SESSION_SECRET` 环境变量。

默认地址为 `http://127.0.0.1:8765`。需要手机审核时，将 `web.host` 配为 `0.0.0.0`，在同一局域网内通过电脑 IP 访问；不要把该服务直接暴露到公网，远程访问优先使用 Tailscale 等私有网络。

Web 服务启动 15 秒后会执行第一次消息同步，之后按 `collection.interval_minutes` 自动导入。每次同步会向前重叠 `collection.overlap_minutes`，并通过消息 ID 去重，避免数据库快照延迟导致漏消息。QQ 未运行时任务会保留失败状态，并在下个周期重新检测。

摘要任务独立按 `summary.hour` 和 `summary.minute` 每日执行，也可在总览页手动生成。失败后默认每 15 分钟重试，最多尝试 3 次；服务重启后会从 `jobs` 表恢复当天状态。AI 请求默认对网络错误、408、429 和 5xx 做最多 3 次指数退避重试，其他 4xx 和响应格式错误立即失败。相关配置：

```yaml
summary:
  max_attempts: 3
  retry_interval_minutes: 15
ai:
  provider_priority: [compatible]
  base_url: https://api.deepseek.com
  model: deepseek-flash
  json_mode: true
  max_retries: 3
  retry_base_seconds: 2
qq_bot:
  max_retries: 3
  retry_base_seconds: 60
```

AI 服务失败不会阻止消息采集。QQ Bot 通知会先进入 `send_log` 持久队列，临时失败按指数间隔重试，达到上限后保留失败状态。CLI 入口：

```powershell
D:\CodexTools\python\Scripts\qq-digest.exe run-daily --config-path config/config.yaml
```

启用 QQ Bot 后，白名单用户可以通过私信审核候选：`候选`、`查看 12`、`入库 12 13`、`忽略 14 原因`、`稍后 15`。原有 `/list`、`/view`、`/confirm`、`/ignore`、`/later` 命令仍然兼容；批量入库逐条执行，个别 ID 失败不会撤销已经成功的条目。

## 安全边界

- 不以写模式打开 QQ 原始数据库。
- 数据库解密输出放在配置的 `ntqq.db_dir`，刷新失败保留上一份可用副本。
- API key、会话密钥和 QQ Bot 密钥不进入 Git。
- 只有经过登录的 Web 会话可以调用业务 API。
- AI 只接收经过长度限制的文本上下文，不上传媒体文件本体。
