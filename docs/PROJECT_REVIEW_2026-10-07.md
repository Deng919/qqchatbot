# 功能与代码精简检查

检查日期：2026-10-07。项目：`D:/Desktop/AI/chatbot`。检查基线：`3f89ff1`。

## 结论

程序的主要问题是旧页面没有退场、部分功能边界重叠、入口层级重复，以及网页主程序承担太多职责。没有证据支持把全部扩展功能或大量代码直接删除。建议围绕“读摘要、查原文、留知识”收敛日常界面，待办、提醒、话题跟踪按需使用，维护功能留在设置和群聊管理。

本轮已清理确定无用的重试函数、旧快照函数及未使用导入，保留现有功能和用户数据。下列产品归并是建议，尚未修改桌面界面。

## 最值得做的三项界面收敛

1. **旧页面退场**：`/catchup`、`/ai-settings` 跳到统一页面，移除旧模板和对应构建清单；分别保留阅读状态、AI 设置服务。旧链接参数和访问控制要有回归。
2. **内容与维护分组**：常驻内容入口保留阅读摘要、知识库、收藏；开启后再显示待办、话题和提醒。知识整理并入知识库，异常处理并入运行记录。现有一级“摘要”和刚增加的二级“阅读摘要”保留，后者是用户明确要求的详情返回入口。
3. **收藏与待办分工**：收藏负责留存，待办负责行动。统一两处问答的名称和来源呈现，避免用户学习两套操作，但继续核验各自证据。

选择这些归并而不是直接删掉全部扩展功能，能减少菜单和维护成本，同时保留用户已存的内容。仅隐藏入口只能减视觉拥挤，不能减代码；彻底删功能会涉及数据和集成场景，目前没有足够使用证据支持。

## 代码检查与已完成清理

检查前生产代码为 **94 个 Python 文件、17,082 行**，有 **45 个 HTML 模板、144 个显式 HTTP／WebSocket 路由声明**。行数包含注释和空行，路由数量包含分页、来源、版本等接口，不能据此推断有 144 项功能。对函数源码跨度至少 10 行的 Python 函数比较函数体 AST，没有完全相同的命中；这只排除了该口径的整段复制，不能排除结构近似的重复。

已清理：

- `pipeline.with_retry` 无生产、脚本或测试调用；实际 AI 客户端、调度与通知队列各自已实现重试。删除它与专用的 `time` 导入，不影响实际重试。
- `refresh._copy_stable_snapshot` 无生产调用，只有两项测试使用。实际 QQ 刷新使用 `_copy_database_snapshot` 同时处理主库与 WAL；删除旧函数，把“源变化后重试／持续变化失败”两项测试迁到当前实现，保留断言。
- 删除 8 个未使用导入：网页主程序的 sqlite3／JSONResponse／load_config、功能路由 Request、更新工作进程 STATE_DIR、采集器 timezone、QQ Bot 通知器 json／Path。
