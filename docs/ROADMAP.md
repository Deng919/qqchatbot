# QQ Digest 迭代路线图

更新日期：2026-10-02
定位：本地 QQ 群消息采集、摘要、检索和知识整理的 Windows 桌面工具。

本文用于确定后续迭代方向。清单中的未勾选项目均为**计划项**，不代表已经实现；完成时应在对应条目中补上版本、日期和验证结果。优先级可根据实际使用反馈调整。

## 当前基础

程序已有 QQ NT 消息增量采集、按群摘要、日期范围报告、关键词搜索、报告问答、候选审核与知识库、QQ Bot 通知、桌面 EXE、存储位置切换、报告导出、开机自启和手动 ZIP 备份。后续优先完善数据可信度、日常处理闭环和故障恢复。

- [x] **P0-01a 多群历史缺口巡检〔增强，2026-10-01 完成〕**：程序运行时默认每 24 小时检查全部已启用群最近 7 个完整自然日，可在采集页调整范围与间隔、关闭自动巡检或手动执行。按群集中展示待补日期和数量，点击预填单日补采范围；失败保留上次成功快照并显示原因，空源库不声称历史完整。只比对当前可读取的源库和归档，不改消息、同步游标或同步状态。472 项测试、宽窄屏设置保存、分页与单日跳转检查通过，审查发现的群数量减少后分页失效已修复。桌面版位于 `D:\Apps\QQDigestDesktop-2026-10-01-P0-01a`，已核对打包模板和新模块并更新桌面入口；实际 EXE 启动仍因此前自动审批审核拦截未验证。源库本身缺失的消息无法核实。
- [x] **P0-02 摘要逐条溯源〔新增，2026-09-29 完成〕**：新生成的日报和范围摘要为概览、话题、结论、资源、任务与未解决问题保存原消息 ID；只接受实际纳入模型上下文的 ID，每条最多 3 个。报告详情逐条展示来源，可打开同群、同报告日期的原消息及前后上下文；无有效引用标「待核实」，旧报告明确说明未记录逐条来源，不自动猜测。无数据库迁移，引用随报告 JSON 保存；单元、接口及本机桥接合成消息测试通过。
- [x] **P0-03 程序内备份与恢复〔增强，2026-09-29 完成〕**：保留手动 ZIP，增加每天／每周自动备份、逐文件 SHA-256、SQLite 完整性及消息表结构校验、恢复预览和设置页恢复流程。恢复前先备份当前状态，目标必须为空目录，旧数据保留，重启后切换。已用真实归档结构验证消息、报告、知识库与配置恢复后的正常启动和检索，并覆盖损坏 ZIP、越界路径、缺失联合主键和恢复期间文件变化。
- [x] **P0-04 失败处理中心〔增强，2026-09-30 完成〕**：新增“异常”页，汇集逐群采集、每日摘要和 QQ Bot 通知的持久化失败，展示任务编号、群、日期、阶段、原因及下一步；支持按原日期重跑日报、重跑增量导入、定向补采和通知重新排队。新任务记录逐群结果及重试来源，只有同一群的后续成功／跳过才标为恢复；重复通知和已恢复任务禁止再重试。覆盖迁移、鉴权、并发状态及失败记录优先展示的测试；全量测试、浏览器窄屏交互和新版 EXE 启动检查通过。
- [x] **P0-05 摘要完整性提示〔新增，2026-09-30 完成〕**：报告列表和详情展示输入覆盖状态、归档与实际纳入条数、低样本、上下文截断、预处理排除及采集量异常；新生成的限制说明随 Markdown/JSON 持久化。总览和日报详情依据同日期最新任务及逐群结果展示失败、无消息跳过、缺报告和未知范围，重跑成功后刷新覆盖状态。旧报告缺少统计时明确“无法确认”，范围摘要只说明选定群与日期的本地归档范围，不声称历史无遗漏。448 项测试、1280/390 宽窄屏浏览器检查及 EXE 打包文件核对通过；本次实际 EXE 启动检查被自动审批审核拦截，尚未验证。

## P1：日常使用闭环

- [x] **P1-01 跨群补看〔新增，2026-09-29 完成〕**：从已生成的各群日报汇集主要话题、结论、资源、任务和未解决问题；可按“上次查看后”“今天”“最近七天”切换，逐条已读状态写入归档数据库。新报告可打开经过同群、同日期校验的原消息及上下文；旧报告和无效引用明确标记。支持分页与窄屏布局，不额外调用 AI。单元、接口和真实浏览器交互测试覆盖筛选、来源及已读。
- [x] **P1-02 任务与待办收件箱〔新增，2026-09-29 完成〕**：最近 30 天有有效原消息引用的日报任务进入待确认建议，经人工确认或忽略后不重复出现；可从搜索到的原消息直接创建。正式待办记录负责人、准确截止日期、状态、群及不可改的来源消息，可编辑、完成、取消和重新打开。待办页及总览提供今天到期和逾期提示；系统通知规则留在 P1-05。服务、接口、浏览器桌面与窄屏流程已验证。
- [ ] **P1-03 话题持续跟踪〔新增〕**：关联跨天、跨群的同一话题，显示进展、最新结论和待解决问题。验收：重复讨论不会在每日报告中成为互不相干的新事项，用户可手动纠正关联。
- [x] **P1-04 摘要纠错与版本记录〔新增，2026-10-01 完成〕**：日报与范围摘要成功生成时保存不可变的 Markdown/JSON 版本快照，可分页查看历史；支持标记遗漏、错误和噪声，记录原段落、修正意见与依据，并标记处理或重新打开。人工意见单独保存，重生成后仍保留并提示旧版意见需重新核实。重新生成需填写原因，只使用原群和原时间窗的本地归档消息，失败保留当前内容；旧报告没有记录精确时间窗时按原自然日范围处理。修复了日报截止边界、连续重生成跨日、文件损坏时范围扩大，以及版本切换期间正文、问答与版本不一致的问题。492 项测试、宽窄屏浏览器交互和独立复审通过；旧版本只能从本次功能启用后保存，先前已被覆盖的内容无法恢复。桌面发布与验证记录见实施计划。
- [ ] **P1-05 提醒规则〔增强〕**：对重点关键词、新资源、任务到期和运行故障分别配置通知渠道、群范围和免打扰时段。验收：可预览触发条件，同一事件不会重复轰炸通知。
- [ ] **P1-06 收藏与稍后处理〔新增〕**：收藏原消息、报告段落、资源和知识条目，形成统一待处理列表。验收：收藏项能从列表打开原内容，并可标记完成或取消收藏。
- [ ] **P1-07 首次使用引导〔增强〕**：引导完成 QQ 数据检测、选群、首次导入、AI 配置、采集计划和结果预览。验收：新用户无需编辑配置文件即可完成常见本机设置，失败步骤提供明确修复建议。
- [ ] **P1-08 桌面版更新与回退〔新增〕**：显示当前和可用版本，更新前备份数据，更新失败时能回退程序版本。验收：更新不会覆盖用户数据；历史版本目录可由程序安全清理，不依赖手动删除正在占用的文件。
- [x] **P1-09 功能开关与精简界面〔新增，2026-10-02 完成〕**：设置页可选择精简界面、全部扩展功能或逐项开启补看、待办、异常、审核、摘要问答、版本纠错、历史巡检；自动采集、自动日报独立设置。关闭后隐藏导航及次级入口、阻止新接口操作，自动巡检/采集/日报分别遵守开关，手动采集和生成保留；不删除数据或中止在途工作，重新开启可恢复。开关随归档备份和迁移，旧数据默认全部开启兼容；本机已按用户选择保存精简预设并核对六类内容数量未变化。501 项测试、宽窄屏设置保存、重开及问答独立使用检查通过，复审发现的路径编号绕过和搜索残留链接已修复。桌面版 `D:\Apps\QQDigestDesktop-2026-10-02-Features` 已打包核对模板和模块并更新桌面入口，实际 EXE 启动仍因先前自动审批审核拦截未验证。

## P2：检索、内容与长期维护

- [ ] **P2-01 全文检索升级〔增强〕**：建立适合中文消息的全文索引，增加发送人、消息类型、群、日期过滤与命中高亮。验收：大量历史消息下仍能快速定位结果，筛选条件可组合使用。
- [ ] **P2-02 全库问答〔新增〕**：在现有报告问答之外，允许按群、时间范围向原始消息提问，回答附可点击来源。验收：无证据时明确说无法确认；不会引用查询范围之外的消息。
- [ ] **P2-03 附件与多媒体内容〔增强〕**：先完整保留文件名、链接、回复和转发关系，再按实际需求支持图片 OCR、语音转写和文档正文提取。验收：每种新增来源均可检索并追溯到原消息，可按类型关闭处理。
- [ ] **P2-04 通用导入导出〔新增〕**：提供结构化 JSON/CSV 导出和可校验的导入流程，支持去重及增量重导。验收：在另一份空数据目录中可重建主要消息及元数据，重复导入不增加重复记录。
- [ ] **P2-05 存储空间管理〔新增〕**：展示数据库、报告、附件与备份占用；提供清理预览和保留策略。验收：清理前可看到影响范围，重要用户数据默认不会自动删除。
- [ ] **P2-06 AI 用量与预算〔新增〕**：统计调用次数、失败率、用量和估算费用，设置月度预算或调用上限。验收：达到上限后暂停付费调用并解释原因，采集本身继续运行。
- [ ] **P2-07 隐私控制〔增强〕**：按群设置是否允许发送聊天片段到云端 AI，提供敏感字段遮盖和发送内容预览。验收：被禁止的群不会进入云端请求；用户能查看本次请求的数据范围。
- [ ] **P2-08 安全设置〔增强〕**：在程序内修改登录密码、管理登录状态；开启局域网访问时提供更严格的访问限制。验收：改密后旧会话按预期失效，错误登录有基本防护。
- [ ] **P2-09 趋势与统计〔新增〕**：展示群活跃度、主题变化、待办完成情况和知识条目增长。验收：统计口径与日期范围清楚，能跳到支撑数据。

## 工程目标：逐步完成模块化拆分

- [ ] **M-01 按功能拆分网页接入**：逐步将 `qq_digest/web/app.py` 中的补看、待办、失败处理、报告、采集和审核接口迁到各自的网页模块。主程序负责组装服务、鉴权及启动，不集中承担全部功能逻辑。
- [ ] **M-02 分离后台调度**：把自动日报、自动采集、通知队列及启动/关闭流程拆到独立调度模块，通过明确的服务接口调用业务功能，并统一遵守功能开关。
- [ ] **M-03 统一模块边界**：每个功能区分业务服务、数据访问、网页接口和页面；共享鉴权、任务互斥、配置及错误处理复用公共模块。优先避免功能之间通过网页主程序互相调用。
- [ ] **M-04 每次拆分验证兼容**：配合实际迭代小步迁移，保留 URL、数据和用户行为，运行相关回归测试；不为拆分重写全部系统。验收：功能可独立定位、修改和测试，主程序明显缩小，新功能无需继续堆入主程序。

- **2026-10-02 总览统计卡片跳转**：群组卡片打开群组管理，归档消息卡片打开已选“聊天消息”的搜索，摘要卡片打开摘要列表；审核开启时，待审核卡片打开审核列表。增加跳转箭头、悬停反馈和键盘焦点，保留统计刷新与功能开关行为。95 项网页及桌面相关测试通过，合成数据下完成 1280/390 宽窄屏、鼠标跳转和键盘回车检查，浏览器无警告或错误。桌面版 `D:\Apps\QQDigestDesktop-2026-10-02-Links` 已打包并核对页面与源码一致，桌面快捷入口已更新；实际 EXE 启动仍因先前自动审批审核拦截未验证。

## 推荐实施顺序

1. **先做 P0-01 → P0-02 → P0-03**：确认消息没有漏、摘要有证据、数据能恢复。
2. **再做 P1-01 → P1-02**：形成“补看消息 → 提取行动 → 跟进完成”的日常流程。
3. 依实际使用反馈完成其余 P0/P1；P2 按消息规模、成本和用户需求选择。

每项进入开发前，应补充具体界面、数据结构、迁移方式和可验证的边界条件。完成后更新本文状态，并在发布说明中记录对应版本。
