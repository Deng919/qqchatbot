 # 群聊分类体系

 ## 用途

 本文档定义 QQ Digest 对群聊的分类标准。每个群在 `config/config.yaml` 中配置 `category` 字段，AI 摘要和候选筛选会根据分类采用不同策略。

 分类不依赖群名称猜测，完全由用户在配置中显式指定。如果用户不确定某个群属于哪类，可以先用 `general`，观察几天的摘要结果后再调整。

 ## 分类一览

 | 代号 | 中文名 | 典型特征 |
 |------|--------|----------|
 | `tech` | 技术群 | 编程、运维、架构、工具链讨论为主 |
 | `resource` | 资源群 | 以分享链接、文档、教程、工具为主 |
 | `project` | 项目群 | 围绕具体项目协作，有任务分配和进度同步 |
 | `study` | 学习群 | 课程、考研、考证、自学互助 |
 | `general` | 通用群 | 闲聊为主，混合各类内容，无明确主题 |

 ## 分类定义

 ### `tech` 技术群

 **内容特征：**
 - 消息中频繁出现代码片段、命令行、配置文件、报错日志
 - 讨论集中在编程语言、框架、运维工具、开发流程
 - 常见内容：技术选型讨论、问题排查、经验分享、工具推荐

 **摘要侧重：**
 - 技术结论和解决方案优先
 - 代码片段不进摘要正文，只记录结论和关键思路
 - 工具推荐需要标注用途和适用场景

 **候选侧重：**
 - 有复用价值的技术方案、踩坑经验、工具配置
 - 排除：一次性的 debug 过程、环境特定的问题排查

 ### `resource` 资源群

 **内容特征：**
 - 消息以链接分享为主，文字说明通常较短
 - 常见内容：教程链接、文档链接、工具网站、开源项目
 - 讨论围绕资源的评价和补充

 **摘要侧重：**
 - 按资源类型分组，不按时间线
 - 每个资源记录：标题、链接、分享者评价、适用场景
 - 对重复分享的同类资源做合并

 **候选侧重：**
 - 高质量、可长期访问的资源链接
 - 排除：临时活动页面、需要登录才能查看的内容、新闻资讯类时效性内容

 ### `project` 项目群

 **内容特征：**
 - 有明确的任务分配、截止日期、进度同步
 - 常见内容：需求讨论、排期确认、问题阻塞、进度汇报
 - 消息通常围绕特定 feature 或 bug 展开

 **摘要侧重：**
 - 任务和承诺单独提取，标明负责人和隐含截止日期
 - 阻塞问题和风险项突出
 - 决策记录：什么决定了、为什么

 **候选侧重：**
 - 项目经验教训、可复用的流程模板、架构决策记录
 - 排除：具体任务项（这些属于 tasks，不属于知识库）

 ### `study` 学习群

 **内容特征：**
 - 围绕课程、考试、知识点讨论
 - 常见内容：题目求助、知识点讲解、学习计划、资料分享
 - 常有周期性（考前密集、假期稀疏）

 **摘要侧重：**
 - 知识点讨论按主题归类，不按时间
 - 错题和易错点单独标注
 - 学习计划和打卡记录归入 tasks

 **候选侧重：**
 - 高质量的知识点总结、解题方法、学习路径
 - 排除：具体题目答案（时效性短）、个人学习计划

 ### `general` 通用群

 **内容特征：**
 - 话题分散，技术、生活、闲聊混合
 - 信号噪声比低，有效信息密度不确定
 - 可能包含任何类型的内容

 **摘要侧重：**
 - 只提取有信息量的讨论片段，不强行总结闲聊
 - 如果当天没有有效讨论，摘要可以为空，不要编造话题
 - 篇幅按有效信息密度自适应，不用闲聊凑数

 **候选侧重：**
 - 标准从严：只有能脱离群上下文独立理解的内容才入选
 - 排除：群内梗、回应性内容、需要知道前因后果才有意义的片段

 ## 配置方式

 在 `config/config.yaml` 中为每个群指定 `category`：

 ```yaml
 groups:
   - group_id: 123456789
     name: "Python 开发交流"
     category: tech
     daily_summary: true
   - group_id: 987654321
     name: "前端资源汇总"
     category: resource
     daily_summary: true
   - group_id: 555555555
     name: "XX 项目协作群"
     category: project
     daily_summary: true
   - group_id: 111222333
     name: "考研互助"
     category: study
     daily_summary: false
   - group_id: 777888999
     name: "摸鱼群"
     category: general
     daily_summary: true
 ```

 未配置 `category` 的群默认为 `general`。

 ## 分类与自适应摘要

 `category` 决定 AI 理解和筛选内容时采用的业务重点，输出长度和主题数量则由当次聊天的信息密度自动决定。无需再为群配置精简或详细模板。

 | 维度 | 规则 |
 |------|------|
 | 摘要策略 | 按 `category` 使用 tech/resource/project/study/general 对应规则 |
 | 输出长度 | 根据信息密度自适应；内容少则简短，内容多则展开 |
 | 主题数量 | 通常 3–8 个；实际有效主题不足时不凑数 |
