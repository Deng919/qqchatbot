# 四个主入口实施计划

> 使用 subagent-driven-development：独立消息浏览接口由子代理实施；主代理负责导航、设置与群聊页面，随后完成需求及质量复审。

**目标：** 按用户已批准的方案，将日常入口统一为摘要、消息、群聊、设置，已有功能在对应次级区域可找到。

**结构：** 沿用 FastAPI/Jinja/原生 JS，保留旧 URL 与业务接口。导航映射集中到共享模板；设置按分类展示并复用 AI 表单，运行记录复用原总览页面。消息浏览新增独立模块，空关键词浏览归档，有关键词使用现有搜索。

## 入口和页面约定

- `/` 默认显示摘要阅读，`/reports` 保持；原总览迁到 `/overview` 作为设置 → 运行记录。登录后直接阅读。
- 四主导航始终固定。子页面按所属入口高亮；摘要、消息、群聊、设置都有用途描述。待办/知识整理仅在开启时出现在内容区的更多工具中。
- 消息页面 `/search` 改为“消息”，默认浏览最近七天归档，不触发采集。群、日期、关键词可组合；关键词搜索仍支持消息、摘要、知识。使用已有上下文/待办入口。
- 群聊默认仅显示群名、关注开关、更新状态、最新摘要入口和操作；点击详情编辑摘要、分类、关键词、首次导入、知识提取。危险删除仅在高级设置。添加流程先展示扫描面板；更新消息明确进入预填日期和群的更新页 `/collect`，高级维护保留巡检/补采。
- 设置分类：AI 连接、自动运行、界面与功能、存储与导出、备份与恢复、运行记录。原控件 IDs/保存行为保留；自动任务与扩展开关分开表单保存，避免未保存的另一分类被覆盖。旧 `/ai-settings` 仍可直接访问，显示所属分类导航。
- 自动运行分类使用既有开关和配置读数；本次不新增后台任务系统或统一重写生成流程。
- 简短全局运行状态显示真实 `/api/health` 状态，链接到运行记录；不在每页重复统计和任务表。
