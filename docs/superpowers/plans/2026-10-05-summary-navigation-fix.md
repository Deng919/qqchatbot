# 摘要生成后的历史阅读修复

用户确认问题为之前日期或其他群的摘要打不开。合成数据验证旧报告 API、原日期列表和要点仍可读取，没有删除旧记录。

## 已复现根因

1. 阅读本次结果收窄日期与群，重置又回今天；要点视图隐藏历史入口。
2. 切换群、日期或阅读方式不取消待返回的详情请求；迟到详情响应覆盖新导航。
3. 列表视图绘制没有统一遵守详情状态，后台刷新可能重新露出列表。
4. 迟到要点失败隐藏历史分页，初始群回调和详情跳转覆盖主动导航。
5. 初始访问时间返回前切换新增筛选会丢弃有效截点；改为单独维护截点修订号，在截点返回后更新新增要点。

## 修复范围与状态约束

- 历史入口在各阅读方式可见，打开全部群、全部日期的报告卡片，保持分页。
- 阅读本次结果保存之前阅读条件；提供返回之前阅读，恢复群、日期、方式、页码及滚动位置。刷新可恢复这一返回上下文。
- 所有主动列表导航先取消详情请求、问答和来源弹层；详情打开期间后台列表刷新不改变详情可见性。
- 请求编号保证最后一次报告选择有效；返回、切换条件和关闭使旧响应失效。
- 生成、阅读范围和详情状态分别维护，生成结束仅刷新现有列表，不强制打开报告或覆盖用户当前筛选。
- 不改变版本纠错开关，不迁移或删除已有摘要。
