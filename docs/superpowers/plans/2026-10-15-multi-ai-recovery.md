# 多 AI 设置与存储兼容修复

日期：2026-10-15

## 范围与原因
上一轮实现包含多连接和用途路由，但设置页缺少新连接测试按钮，保存未绑定页面读取版本；密钥先后提交、共享密钥清理及备份迁移还有缺口。本轮只完成既定多 AI 功能的修复与验收，不恢复已取消的 P2-07，不增加新的渠道协议或修改公开版渠道限制。

## 实施
- [x] 版本化连接读取／保存／删除／用途／测试接口；复用首次设置的原子配置写入器、跨进程活动租约及物理 worker 取消保护。
- [x] 配置锁在 worker 中等待，避免连接测试等待时阻塞 ASGI 事件循环；固定文本测试最多一次请求、最长 30 秒。
- [x] 写入独立版本密钥，再提交 YAML 引用；提交前失败清理新文件，提交后异常不删除活动引用。签名使用已提交字节，免于提交后读文件失败。
- [x] 仅清理本程序为对应连接创建且已无引用的密钥；支持默认连接的相对路径引用，清理失败明确返回保存结果与保留提示。
- [x] 独立模板脚本提供测试按钮、版本冲突提示、忙态防重入、连接／用途草稿互不覆盖；可关闭接口 JSON 模式。
- [x] profile 密钥纳入备份声明、ZIP 校验、恢复双阶段路径回填、存储迁移及缓存清理保护；外部文件仍保留外部身份。
- [x] 修复全量回归发现的版本管理旧路径常量引用，补测新连接密钥的版本清理保护。
- [x] URL 端口、空查询／片段、控制字符校验；连接 ID 不再暗示图片能力；无效用途引用明确失败。
- [x] 新增永久 Python／CJS 回归、独立复核、真实宽窄屏浏览器、隔离 EXE 和源码／模板完整性核对。
- [x] 最终全量回归 1491 项通过、2 项权限跳过；正式桌面入口交付，保留上一版回退。主工作区采用快进合入。

验收与交付证据见 [验收记录](../specs/2026-10-15-multi-ai-recovery-verification.md)。

## 设计边界
复用现有 YAML 与权限文件，不引入独立配置数据库或崩溃恢复事务框架。突然中断可能留下未引用的版本密钥文件，但配置不会因密钥稍后安装而指向未就位的新文件；这不是对断电／底层文件系统损坏的全面保证。测试只使用合成密钥、固定文本及本机模拟接口；不调用真实 AI／QQ 或发送通知。
