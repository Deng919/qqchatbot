# Inbox UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the selected B inbox interface using existing summary data and actions.

**Architecture:** Retain the current reading service and request tokens. Add a small presentation controller receiving validated list responses and a scoped workspace stylesheet. Existing report details remain the full-report reader in the right pane.

**Tech Stack:** FastAPI, Jinja, vanilla JavaScript/CSS, pytest, existing CJS harness, independent Chromium.

**Spec:** `docs/superpowers/specs/2026-10-18-inbox-ui-design.md`

## Global Constraints

- No new dependencies or data schemas; preserve existing services, feature switches and typed report keys.
- Keep production config, archive, reports, credentials and caches out of Git.
- Use independent Chromium; never automate or close Codex IAB tabs.
- User selected B and previously requested inline execution without repeated approval. Continue in the attached worktree.

## Review Focus

- Date/group/page changes must invalidate selection before late responses can render.
- Read-state saves must not overwrite a newer point selection.
- Desktop automatic selection must never mark anything read; mobile must stay in the list.
- Feature-disabled source/collection actions remain governed by existing controls.
- Long labels, empty results and full-report deep links must remain usable on narrow screens.
