# Interaction Logic Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 让现有界面的滚动、展开、返回、筛选和失败恢复符合一致的使用预期，修复经复现的问题。

**Architecture:** 沿用页面现有状态和接口，不增加通用交互框架。群摘要仍按需展开，但自动连续读取本群各页，保留两排滚动区；其他页面依据独立审计和复现结果作最小修正。

**Tech Stack:** FastAPI、原生 HTML/CSS/JavaScript、pytest、Node CJS、独立 Chromium/Playwright。

**Spec:** 用户本轮要求：“既然已经展开了能上下滑动为什么还有点击更多摘要……全部检查一下操作逻辑，要符合人的常识”。

## Global Constraints

- 不使用 Codex 内置浏览器；不操作无关进程。
- 不调用真实 QQ／外部 AI 来验证界面，不提交本地配置、凭据或聊天数据。
- 原有两排展开、来源核对、手动已读和偏好数据保留。
- 本轮在当前适用工作分支执行；已有无关未跟踪文件不纳入修改。

## Review Focus

- 展开只需一次操作，后台分页不应要求用户再次点击“更多”。
- 翻看时追加数据不能跳回顶部、替换焦点或重复条目；收起／换筛选后旧请求不能污染新页面。
- 进入详情再返回，应回到刚才的位置和卡片。
- 请求失败不能让新筛选对应旧内容、永久加载中或无重试入口。
- 取消、返回、修改源和保存应与界面显示的选择、草稿及实际状态一致。
