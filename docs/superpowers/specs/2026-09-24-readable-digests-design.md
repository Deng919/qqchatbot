# 更自然的群聊摘要设计

用户已确认 2026-09-24 的质量检查建议：保留 DeepSeek V4.1 Flash，优先修正摘要写作规则与报告呈现，再用同一批消息对照重生成。

## 目标

让报告像给群成员看的速览，而非为填满栏目写的正式纪要；不牺牲事实边界和知识候选筛选标准。

## 方案选择

- 换模型：成本和结果不可控，旧模型生成的报告也有同类问题，暂不采用。
- 生成后再让模型改写：增加一次调用和事实漂移风险，暂不采用。
- 调整原始提示词及确定性排版：保留现有 JSON 接口和模型，只改变写作约束与展示，采用此方案。

## 规则

1. 概览直说当天值得知道的内容，通常 1–2 句；话题数量和字数不设目标。话题按信息价值而非消息数量筛选，临时邀约、短期推广、重复感叹不独立成话题。
2. 摘要使用简洁、自然、中性的中文；不用“群内围绕……展开讨论”“未形成统一结论”等固定套话。概览、话题、结论和待核实项各司其职，不重复同一事实。
3. 群友观点与已核实事实分开。学校政策、健康、价格和数字等外部事实，若只有群友说法，用归属词标明未经核实；没有原文或可靠链接时不得写“已确认”。真正的群内决定或验证结果才进入结论；普通疑问或含糊意愿不写成任务。
4. Markdown 仅显示有内容的栏目；采集数量、提取结果保留在报告 JSON 的 `diagnostics`，只有上下文截断提示保留在正文。当前 Web 详情展示 Markdown，因此无需新增前端交互。
5. 待办提取不把“我记得……”一类回忆句当待办。保留显式 TODO 和明确的未来行动。
