# 版本列表加载性能

用户要求继续优化，并已授权无需反复征求意见。本轮只处理已记录的版本页慢问题，复用已批准的本机版本管理流程。

2026-10-16 在本机 32 个登记包上 cProfile 实测 snapshot 为 87.986 秒，其中 `_files` 为 86.984 秒，约 6.3 万次文件哈希、117 万次 stat。证据：`D:\Cache\QQDigestVersionPerformance-20261016\baseline-profile.log`。这不是仅由列表重复读取登记表造成的问题。

选择：列表只验证版本清单与已登记记录一致，显示“操作前校验文件”；切换、回退、清理仍使用已有 `verify()` 全量检查，操作不信任列表结果。完整扫描不是查看列表的必要条件，列表不得声称程序文件刚刚校验通过。

对照方案：保留全量扫描并减少 stat，只能缓解且仍读取全部历史文件；并行扫描增加 I/O 和线程调度；缓存哈希需要额外失效机制。当前需求不需要以上复杂性。

实现只涉及 `desktop_releases.py`、版本页状态文案、现有回归和后台标识；不新增 API、持久状态、自动清理或外部服务。清单损坏／指纹变化／目录链接仍拒绝该项；列表之后程序文件被篡改、缺失或多出时，操作必须拒绝。

验收：观察新增测试先失败再通过；覆盖登记清单变化、程序修改／多余／缺失、链接和清理保护；实测同机列表耗时并核对列表无程序文件内容读取；宽窄屏源浏览器与实际隔离 EXE，构建完整性和原配置保护。
