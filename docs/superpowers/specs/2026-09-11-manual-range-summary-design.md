# QQ Digest 手动范围总结设计

## 背景

QQ Digest 已能按固定时间窗运行每日报告，但用户不能在 Web 页面选择指定群组和历史日期重新生成摘要。第一阶段增加“手动范围总结”，让用户从本地归档中选择最多七个自然日的消息，并为一个或多个群分别生成报告。

本功能复用现有消息清洗、AI 摘要、报告写入和候选审核能力。它不触发 NTQQ 刷新或采集，不发送 QQ Bot 通知，也不实现长聊天分块、跨群合并或报告版本历史。

## 目标

1. 在报告页面选择一个或多个已启用群组、开始日期、结束日期和摘要详细程度。
2. 每个群独立生成范围报告，单群失败不影响其他群。
3. 只读取本地 SQLite 归档，不在摘要过程中改变 NTQQ 数据源。
4. 默认沿用各群模板，同时允许临时统一覆盖为精简或详细模板。
5. 相同条件和相同输入直接复用报告；输入变化时安全更新原报告。
6. 范围报告照常提取资源与经验候选，但不发送通知。
7. 日报和范围报告在现有报告页面统一展示并明确区分。

## 非目标

- 不把多个群合并为一份报告。
- 不允许超过七个自然日的时间范围。
- 不实现 token 级或消息级分块摘要；消息仍过多时沿用当前按完整消息行保留最近上下文的策略，并明确显示截断说明。
- 不从 NTQQ 自动补采缺失消息。
- 不增加自定义提示词编辑器。
- 不增加范围报告版本历史、删除、下载、分页或全文检索。
- 不新增 CLI 命令。
- 不修改每日任务的时间窗和通知行为。

## 架构

### 手动总结服务

新增 `ManualSummaryService`，输入为 `ManualSummaryRequest`：

- `group_ids`：一个或多个群 ID。
- `start_date`：开始自然日。
- `end_date`：结束自然日。
- `detail_mode`：`group`、`concise` 或 `detailed`。

服务负责请求校验、日期转换、逐群读取归档、复用判定、单群故障隔离和结果汇总。它不直接采集消息，也不创建通知。

新增可复用的单群摘要生成组件，从现有 `DailyPipeline` 中提取以下职责：

1. 清洗归档消息并构建 AI 上下文。
2. 调用摘要提供商。
3. 生成结构化摘要、确定性提取和候选草稿。
4. 渲染 Markdown 和 JSON 内容。

报告发布组件负责原子写入文件、在数据库事务中创建候选及记录报告，并在受控失败时回滚。日报继续先完成采集，再把每群归档消息交给生成组件；手动服务则直接查询归档后调用同一组件。通知和整批任务状态仍由各自的上层服务处理。这样日报与手动总结共享内容生成规则和发布安全性，但保留不同的触发方式和副作用。

报告渲染器增加报告类型和时间窗元数据。日报标题继续使用“群名日报”，范围报告标题使用“群名范围摘要”，避免历史范围被误认为单日日报。

### 时间窗

日期按系统摘要配置中的时区解释。以 `Asia/Shanghai` 为例，选择 2026-09-01 至 2026-09-07 时，实际查询区间为：

- 开始：2026-09-01 00:00:00 +08:00，包含。
- 结束：2026-09-08 00:00:00 +08:00，不包含。

归档新增左闭右开的范围查询方法，避免相邻范围在午夜重复纳入同一条消息。选择天数按自然日计算并包含首尾日期，最大为七天。

### 模板解析

`detail_mode=group` 时，每个群在执行时解析其当前配置的 `template`。`concise` 和 `detailed` 则临时覆盖所有选中群的模板，但不更新群组配置。

范围报告同时保存用户选择的 `detail_mode` 和实际使用的 `effective_template`。因此页面可以解释报告为何使用某种详细程度，群配置发生变化后重新运行也能记录新的实际模板。

### 操作协调

现有 `OperationCoordinator` 增加 `manual_summary` 操作。它与 `refresh`、`collect`、`sync`、`daily` 和其他 `manual_summary` 全部互斥。

Web 请求无法取得操作权时返回 HTTP 409，并携带当前活动操作的结构化信息。服务退出或抛出异常后必须释放操作状态。

## 数据模型

### `manual_reports` 表

范围报告使用独立表，避免重建现有 `reports` 表及其 `UNIQUE(group_id, report_date)` 约束。字段包括：

- `manual_report_id`：自增主键。
- `group_id`：来源群组。
- `start_date`、`end_date`：包含首尾的本地自然日。
- `detail_mode`：用户选择的详细程度。
- `effective_template`：实际使用的模板。
- `markdown_path`、`json_path`：报告文件路径。
- `candidate_ids`：本次报告创建的候选 ID JSON 数组。
- `input_fingerprint`：按稳定顺序计算的消息输入指纹。
- `source_message_count`：归档消息数量。
- `created_at`、`updated_at`：UTC 时间戳。

唯一约束为 `(group_id, start_date, end_date, detail_mode)`。同一群、同一范围和同一详细程度只保留一个当前版本。

`detail_mode=group` 的记录在群模板变化后仍更新同一条记录，同时刷新 `effective_template`。精简和详细覆盖分别拥有独立记录。

### 文件命名

范围报告使用可辨识且稳定的名称：

```text
range__<start-date>__<end-date>__<group-id>__<detail-mode>.md
range__<start-date>__<end-date>__<group-id>__<detail-mode>.json
```

例如：

```text
range__2026-09-01__2026-09-07__123__concise.md
```

文件继续写入现有报告目录。文件名不包含群名，避免非法字符和群名变化导致路径失效。

### 重复运行与候选

服务对所选范围内、按稳定顺序排列的消息计算指纹：

- 已有报告且指纹、实际模板均未变化：标记为复用，不调用 AI，不创建候选，也不改写文件。
- 输入或实际模板变化：生成新内容，原子替换 Markdown/JSON，再更新数据库记录。
- 生成失败：保留旧报告文件、数据库记录和旧候选关系。
- 更新成功：删除旧报告关联且状态仍为 `pending` 的候选；已确认、稍后处理或已忽略的候选保留。新候选写入现有候选表并出现在审核页。

文件、报告记录和候选按以下顺序发布：

1. 在内存中完成摘要与候选草稿，不改变持久化状态。
2. 在目标目录准备并 `fsync` 完整的 Markdown/JSON 临时文件，同时为已有目标保留可恢复备份。
3. 开启数据库事务，创建新候选、更新范围报告记录，并删除旧报告仍为 `pending` 的候选。
4. 在数据库事务提交前把两份临时文件发布到稳定目标路径；文件发布失败则回滚数据库并恢复旧文件。
5. 提交数据库事务；提交失败则恢复旧文件并清理新文件和临时文件。
6. 文件与数据库均成功后删除备份。

候选创建、报告记录更新和旧待审核候选清理必须使用同一个数据库事务。这样所有可控异常都不会让报告文件、报告记录或候选关系停留在跨版本状态。进程在文件替换与数据库提交之间被强制终止仍不是跨文件系统事务；后续不可变版本报告可以彻底消除该极小窗口。

删除群组时，现有群组清理流程同时删除该群的 `manual_reports` 记录和范围报告文件，避免孤立数据。

## Web 页面与接口

### 页面交互

现有 `/reports` 页面的标题由“每日摘要”调整为“摘要报告”，并增加“生成范围摘要”按钮，打开范围总结面板。表单包含：

- 可搜索、多选的已启用群组列表。
- 开始日期和结束日期。
- 摘要详细程度：跟随群组、精简、详细。
- “已选择 X 个群，共 Y 天”的提交前摘要。

默认日期为当前配置时区中的当天，默认详细程度为“跟随群组”。用户可选择最近任意日期，但首尾合计不得超过七个自然日。

桌面端使用右侧抽屉；窄屏使用占据主要可视区域的面板。运行期间禁用表单和提交按钮，完成后自动刷新报告列表。

原“立即生成摘要”按钮改名为“生成今日日报”。报告列表新增类型、时间范围和模板信息，用“日报”或“范围”标签区分记录。详情继续显示 Markdown，并在范围报告中显示完整日期范围和实际模板。

### 创建接口

`POST /api/reports/range` 请求体：

```json
{
  "group_ids": [123, 456],
  "start_date": "2026-09-01",
  "end_date": "2026-09-07",
  "detail_mode": "group"
}
```

成功响应包含：

- `status`：`success` 或 `partial_success`。
- `created_reports`：新建或更新的范围报告。
- `reused_reports`：输入未变化而直接复用的范围报告。
- `skipped_groups`：没有归档消息的群及原因。
- `failed_groups`：失败群、失败阶段和安全的错误摘要。

只要存在失败群，状态为 `partial_success`。全部生成、复用或因无消息正常跳过时为 `success`。

### 列表与详情接口

`GET /api/reports` 继续作为统一列表入口，将日报和范围报告规范化为相同的展示结构。每条记录增加：

- `report_kind`：`daily` 或 `range`。
- `report_key`：带类型前缀的稳定字符串，例如 `daily:12`、`range:8`。
- `window_start_date`、`window_end_date`。
- `effective_template`。

新页面通过 `GET /api/reports/{report_kind}/{report_id}` 读取详情，避免日报 ID 与范围报告 ID 冲突；`report_kind` 只允许 `daily` 或 `range`。现有 `GET /api/reports/{report_id}` 数字日报详情路径保留兼容。

## 校验与错误处理

请求必须满足：

1. 至少选择一个群。
2. 所有群均存在且处于启用状态。
3. 群 ID 不重复。
4. 日期采用严格的 `YYYY-MM-DD` 格式。
5. 开始日期不晚于结束日期。
6. 范围包含首尾时不超过七个自然日。
7. `detail_mode` 仅允许 `group`、`concise` 或 `detailed`。

校验错误返回 HTTP 422。任务冲突返回 HTTP 409。只有服务级预检或数据库不可用等整批错误返回 HTTP 500。

每个群有独立异常边界：

- 无消息属于正常跳过，不创建空报告。
- AI、报告文件或候选处理失败时记录群名、阶段和简短错误，继续处理下一群。
- 用户可见错误不得包含聊天原文、令牌、密钥或完整的上游模型响应。
- 本地日志记录异常类型、群 ID 和堆栈，便于诊断。

当消息超过当前 `max_context_chars` 时，仍按完整消息行保留最近内容，并在报告数据质量章节明确写出原始消息数、纳入消息数、丢弃消息数和上下文截断情况。第二阶段的分块摘要将替换这一限制。

## 任务记录

手动范围总结写入现有 `jobs` 表，任务类型为 `manual_summary`。状态沿用：

- `success`：全部群生成、复用或正常跳过。
- `partial_success`：至少一个群失败。
- `failed`：整批任务未能进入逐群处理或服务级失败。

任务错误字段只保存失败群的结构化安全摘要，不保存消息正文。

## 测试策略

实现遵循测试驱动开发，覆盖以下层次：

### 单元测试

- 严格日期解析、开始结束顺序和七天上限。
- 本地时区自然日到左闭右开时间窗的转换，包括午夜边界。
- `group` 模式解析群模板，覆盖模式不修改群配置。
- 范围报告文件名稳定且不包含群名。
- 输入指纹相同时复用，消息或实际模板变化时重新生成。

### 服务与归档测试

- `manual_reports` 初始化和旧数据库无损升级。
- 多群分别生成报告。
- 单群 AI 或文件失败后继续其他群。
- 无消息群正常跳过且不创建空报告。
- 更新失败时旧文件、旧记录和候选保持可用。
- 更新成功后只删除旧的待审核候选。
- 手动服务不调用采集器、不创建 QQ Bot 通知。

### Web 测试

- 未登录用户无法访问创建和详情接口。
- 请求校验返回 422，操作冲突返回 409。
- API 返回新建、复用、跳过和失败群明细。
- 报告列表同时呈现日报和范围报告。
- 表单包含群搜索、多选、日期和详细程度控件。
- 运行中禁用提交，完成后刷新列表并显示结果摘要。

### 回归与浏览器验证

- 运行完整 pytest 套件。
- 执行 Python 编译检查和差异格式检查。
- 在真实浏览器中验证桌面与移动端布局。
- 验证多群提交、七天校验、部分成功提示、报告列表刷新和详情打开。
- 检查浏览器控制台没有新增错误或警告。

## 兼容与迁移

现有 `reports` 表、日报文件、日报 API 数字详情路径、配置文件和候选记录保持可用。数据库启动时只新增 `manual_reports` 表和必要索引，不重建或删除现有表。

现有日报继续使用原来的报告命名和唯一约束。统一列表 API 只增加字段，不删除现有字段。范围报告的独立表是第一阶段的兼容边界；后续“报告档案管理”可以在明确迁移策略后统一日报、范围报告和版本历史。

## 完成标准

- 用户可以在报告页选择多个已启用群、最多七个自然日和摘要详细程度。
- 每个群独立生成一份范围报告，并且只读取本地归档。
- 相同输入复用，变化输入安全更新，失败不破坏旧报告。
- 范围报告产生候选但不发送 QQ Bot 通知。
- 一个群失败不影响其他群，页面显示生成、复用、跳过和失败明细。
- 日报与范围报告在同一列表中清楚区分并能打开详情。
- 所有新旧测试通过，桌面和移动端关键流程通过真实浏览器验证。
