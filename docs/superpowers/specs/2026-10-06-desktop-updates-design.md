# P1-08 桌面版更新与回退设计

状态：用户于 2026-10-06 批准本机版本管理方案；已实现并通过验收。

## 目的与范围

在「设置 → 版本更新」查看当前版本、可用版本、上次切换结果和可回退版本。切换前备份用户数据；启动失败恢复程序入口；程序负责清理受管理的旧版本。

推荐先使用本机发布目录 `D:\Apps`，只纳入明确登记并通过校验的 QQ Digest 发布包。另一种方式是接入用户指定的在线发布地址，但需要另行确定下载清单、可信来源及验证方式。当前项目没有在线更新源，不把本地目录检查称为在线更新。

## 检查结果

- `scripts/build_desktop.py` 创建独立发布目录，并用 `launcher.json` 指向外部配置。可以沿用程序和用户数据分离的方式。
- 发布目录目前缺少版本清单。`pyproject.toml` 的 0.2.0 不能区分历次桌面包，不能以目录名字作为更新顺序、兼容性或删除权限的依据。
- `desktop.py` 已提供服务健康检查及配置指纹，但仅有后台启动标识。需要增加启动事务确认，防止错误连接旧服务被当作更新成功。
- `desktop_settings.py` 已有备份、存储迁移和当前用户自启。新版切换必须保留桌面偏好，并同步程序入口及已有自启设置。
- `Archive` 在打开时执行迁移，没有明确的数据兼容性版本。仅恢复 EXE 不能保证旧版可读取新版写入的数据。
- 当前任务协调器可覆盖切换准备、备份和清理，避免与采集、生成和首次设置并发。

## 推荐流程

### 版本登记与完整性

构建时生成 `release.json`：产品 ID、唯一版本 ID、构建时间、后台 ID、数据兼容性标识和程序文件 SHA-256 清单。配置、偏好和更新状态不计入不可变程序清单，也不随新包覆盖。

扫描仅展示管理清单内、路径位于规定根目录的发布包。切换前重新核对所有程序文件和清单指纹，拒绝遗漏、修改、额外程序文件、路径穿越、链接和 Windows junction。SHA-256 用于完整性检查，不作为发布者身份认证。

现有 FirstUse 包通过构建记录和文件核对登记为初始回退版本。其他无清单历史目录保留，不能自动归入可清理列表。

### 更新事务

1. 在操作锁内重新核对目标版本、当前配置和数据路径，拒绝程序目录与数据目录重叠。
2. 调用已有备份服务并验证结果。备份失败立即停止，当前程序继续运行。
3. 保存事务记录，记录前后程序路径、配置指纹、目标清单指纹、备份路径及原入口信息；不保存密钥正文。
4. 启动独立工作进程，然后关闭当前窗口和本地服务。工作进程等待原进程及其服务停止，超时不切换。
5. 将同一外部配置和桌面偏好写入目标启动设置，启动目标程序。目标需返回本次事务随机令牌、预期后台 ID 和配置指纹，并确认窗口启动。
6. 验证成功后提交当前／回退指针，更新已有桌面快捷方式和启用的自启项。未启用的自启保持关闭。
7. 验证失败先停止目标进程，再恢复原入口、偏好及指针并启动原版本；记录可在设置页读取的失败原因。不出现两个程序同时写同一归档。

事务记录使用原子写入。切换各阶段可被再次启动识别；不把「已发出启动请求」视为完成。工作进程保留自身所在版本，直到退出后才允许清理。

### 数据兼容与回退

每次手动回退同样先备份当前数据。第一版只允许相同数据兼容性标识的程序之间切换；不在用户数据上试运行未知迁移。不同兼容性版本显示不可切换原因，后续需增加对备份副本的迁移预检再开放。

程序回退保留当前用户数据，不自动拿旧备份覆盖新产生的消息。若数据损坏，使用已有「备份恢复」流程恢复到新目录，并明确选择恢复点。初始 FirstUse 回退包需要核实兼容性后才可登记。

### 旧版本清理

先展示可清理版本、大小及保留原因，再由用户选择执行。永久保护当前版本、回退版本、正在运行版本、工作进程版本以及任何包含配置／归档／知识路径的目录。

执行时在互斥锁内重新读取管理清单、解析绝对路径、核对清单指纹及进程占用。只处理受管理根目录内的明确目录，拒绝符号链接和 reparse point。占用或删除失败保留目录并逐项报告；不停止不属于本次事务的用户进程，也不要求用户删除正在使用的文件。

## 模块及入口

- `desktop_releases.py`：版本清单、校验、列表及清理。
- `desktop_updates.py`：准备、备份及可故障注入的交接状态机。
- `desktop_update_worker.py`：事务状态机、进程交接、成功确认及失败回退。
- `desktop_settings.py`：桥接服务和操作锁，不承载版本扫描细节。
- `web/desktop_update_routes.py`：鉴权接口、严格请求校验、线程执行。
- 独立版本更新模板；设置分类入口直接打开，宽窄屏可用。
- `desktop.py`：工作进程模式、启动确认及关闭交接；构建脚本生成发布清单。

## 验收

- 合成程序包：修改文件、路径穿越、大小写重复路径、额外文件、缺失文件、链接／junction、过期指纹和兼容性拒绝。
- 合成数据：备份失败、进程未退出、目标启动失败、健康检查错误、窗口未就绪、配置被外部修改及事务中断，验证原入口和数据保留。
- 清理：当前／回退／运行版本受保护；目录替换和占用失败不会导致越界删除。
- API：未登录拒绝、浏览器无桌面桥接提示、互斥保持至工作线程结束。
- 浏览器：版本列表、失败结果、回退及清理预览，宽窄屏无溢出。
- 实际打包 EXE：使用独立合成配置验证成功交接及故障回退，所有验收结束后恢复原测试启动设置并关闭测试进程。

## 实施补充

已按用户选择使用本机登记版本。清理持有跨进程清单锁，并先移入不可预测的同根临时目录，再复核后删除；删除失败尽量恢复原路径，部分文件已被系统删除时仍可能保留不完整包，后续校验拒绝使用该包。运行包的 EXE/DLL 占用会阻止清理。

启动失败和中断恢复都必须确认回退窗口与后台；无法核实或关闭目标进程时不启动第二个归档写入者，保留「重试回退」及原程序入口。FirstUse 基线使用窗口可见性与预期配置／后台检查；其旧界面不含版本管理页，回退后需从保留的新 EXE 重新进入更新功能。

清单注册、清理及指针提交共用跨进程锁。事务由 worker 独占写入交接阶段，使用独立临时文件原子替换；窗口进程只准备事务。工作进程的结束回调核实自己的操作锁，不能释放随后创建的新操作。
