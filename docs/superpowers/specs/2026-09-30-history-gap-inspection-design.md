# 多群历史缺口巡检

## 范围

按路线图 P0-01a 自动检查所有已启用群的历史中段遗漏。默认程序运行时每 24 小时巡检最近 7 个完整自然日；采集页可关闭自动巡检、调整到 1–31 天及 1–168 小时，并可手动执行。手动执行可选择先刷新解密源库，自动检查沿用已有源库。检查不调用 AI、不补采、不改消息、同步游标或同步状态，只保存巡检元数据。

## 数据与页面

- 新表保存单例设置及逐群最后一次检查状态、成功范围、消息量和按日期的缺失条数。任务继续使用 jobs 表，记录成功、部分成功或失败及逐群结果。
- 比较同一群内的消息 ID；不同群同 ID 互不抵消，重复源消息只计一次。范围为配置时区的完整自然日，排除今天；每群只读取一次源库，归档 ID 按 500 条分批查询。
- 源库缺失、刷新失败、读取中途异常都显示“无法检查”，不推断完整。检查正常但没有可读取的文本时显示“源库无可读取消息”，不声明历史完整。
- 群读取失败保留它上次成功发现的缺口，并注明旧结果日期及当前错误。全局刷新失败不清除之前结果。禁用群不进入下一轮巡检，删除群联动删除巡检状态。
- 采集页增加巡检设置、最近执行情况和分页的逐群结果，优先显示失败及存在缺口的群。逐日缺口直接跳转采集页并预填同一天的开始与结束日期。结果为检查时快照，补采后提示重新巡检确认。
- 自动任务与采集、刷新、日报、群删除等现有操作互斥；冲突时等待下一次轮询。间隔依据持久化的最近执行时间，重启不重复扫描。中断任务在重启后可重新执行。

## 验证

先写失败测试，覆盖历史中段遗漏、去重、同 ID 跨群、时区日期边界、禁用群、失败保留旧结果、补采后重检、设置持久化与校验、启动间隔、并发互斥、接口鉴权和单日补采链接。检查浏览器宽窄屏流程；跑全量测试、构建独立 Windows 版本并核对模板，更新桌面快捷入口和路线图，提交仓库。上轮自动启动 EXE 被审核拦截，本轮不通过换工具重复尝试同一受阻动作。
