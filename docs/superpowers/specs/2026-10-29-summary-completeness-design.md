# Historical summary completeness design

Approved in chat on 2026-10-29: repair missing historical citations against original same-group windows, inspect full archive for previously truncated reports and integrate omissions or later replies, then prevent silent source loss in future summaries. Never invent citations or infer identity from body text; unknown source gaps remain explicitly unknown. Keep backups, prior versions, original report timestamps and source windows. Do not regenerate all correct reports, change market partition, candidates/read states, or store private reports in Git.

Use existing Python, SummaryResponse, ReportWriter and ReportRevisionService. Small inputs keep the current one-call route. Oversized inputs are processed as bounded chronological chunks, splitting a single oversized source with its original ID if necessary. Partial results must cite only each chunk's sources; merge a bounded rolling digest with the next partial, preserving references and chronology, explicitly resolving later replies while retaining genuine disagreement. A failed chunk/merge fails the report and preserves the previous version; never claim full coverage after partial work. Deduplicate and validate merge output against actual prior-stage evidence, never arbitrary whole-archive IDs. No new service, worker, library, UI mode or AI bypass.

Historical repairs use a frozen database/file snapshot, semantic human-agent review and per-field patches. Check all references against the original group's exact time window, preserve diagnostics honestly (past truncation remains in generation metadata; review provenance records full-window inspection separately), and optimistic file-hash/version checking before write. Preserve report generation created_at, create revision timestamps separately. Use all-report rollback with best-effort file recovery and retained backups.
