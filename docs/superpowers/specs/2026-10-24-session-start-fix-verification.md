# 桌面会话启动回归修复

日期：2026-10-24

后续：本轮保留的阅读时间写入占用提示已在[启动阅读修复](2026-10-24-reading-startup-verification.md)中处理；以下是当时的验证与边界。

## 原因与修复

用户反馈 FastStart 版启动后停在「桌面会话未能建立」页面。原测速禁用了自动清理，遗漏了启动阶段的维护并发条件。

桌面启动时自动清理会持有 `storage_mutation`。通用 HTTP 写入门禁按 POST 方法将 `/api/desktop-session` 认定为存储写入并返回 409，页面捕获失败后停留。普通 `/login` 和 `/logout` 已有豁免，新加入的桌面会话入口没有同步处理。

修复仅将桌面会话交换加入认证豁免：它消费内存中的单次凭据、签发 Cookie，不写数据库或文件。原有客户端／Host／Origin、签名、有效期和重放检查保留，数据库及文件写入门禁不变。后端标识更新，避免复用有问题的旧服务。

## 验证与限制

- 新增存储维护、版本维护、存储迁移后只读三项回归，修复前均复现 409，修复后会话可建立、群列表可读、业务 PATCH 仍为 409。
- 203 项相关 Python 测试通过，涵盖桌面认证、存储交接、Web、更新器、发行和摘要读取。未运行 Python 全量。
- 隔离源码原生 WebView 窗口，将真实清理操作的存储占用延长到 8 秒以稳定复现；修复前 `/desktop-start` 显示相同错误并捕获交换状态 409，修复后同条件直接进入 `/reports`。截图和不含凭据的观察结果保存在验收目录。这是受控竞态复现，用户原失败进程没有保留请求日志。
- 最终冻结包复制归档后关闭外部采集／AI 自动任务和备份，开启自动清理，固定本机端口、复用同一隔离 WebView2 配置，三次进程启动均直接到摘要页：2.054／1.740／1.731 秒。签发 HttpOnly 会话、fragment 清除检查通过；没有调用外部 AI 或写入正式归档。
- 120 个模块、56 份模板与源码一致，2192 个清单文件校验通过。独立审查未发现本次豁免导致的认证或业务写入保护缺陷。
- 实际桌面使用原有数据和 WebView 配置，核实新 EXE 身份、摘要页、会话交换成功及未认证 API 401。启动维护期间上次阅读时间写入仍可能被暂时拦住；实际窗口重新载入后恢复，本次没有为阅读状态写入绕过存储保护。
