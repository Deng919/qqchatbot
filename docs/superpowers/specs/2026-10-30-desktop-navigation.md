# Desktop persistent navigation trial

The approved motion prototype uses opaque, sliding page surfaces with a shared sidebar selection and interruptible springs. Bring that feel to the Windows desktop application while preserving each page’s filters, scroll, reading state and draft forms. No white outlines, full-window fade or artificial waiting.

The current server renders independent documents with global page scripts. Keep those documents isolated in same-origin desktop page frames rather than rerunning their scripts in a shared DOM. The desktop-only host retains visited frames, animates their content surfaces, and coordinates top-level history. Each frame retains its original sidebar, page scripts, authentication, API routes and dialogs; inactive frames are inert. Ordinary web routes remain unchanged. The native launch opens the host after its existing proof exchange. First visits can load; revisits reuse the living document. Loading failures keep the previous page usable and offer retry. Only allowlisted same-origin application pages enter this cache. Downloads and external/new-tab links keep native behavior.

Use a small analytic spring per moving content surface and sidebar indicator; retarget without resetting position or velocity. Honor reduced motion dynamically. Let users switch away from drafts without discarding them, but protect all retained dirty pages on actual reload/exit. Route internal reading-history restoration through the existing summary state without reloading the document. A restored inactive page does not rerun its initializer.
