# 启动阅读与后台维护并发验收

日期：2026-10-24

## 原因与修复

上轮仅放开不写存储的桌面认证交换，未处理登录后阅读页自动 POST `/api/summary-reading/visit` 的占用响应。自动清理先获得存储维护权限，阅读时间写入被门禁返回 409；通用 API 弹错误，初始化又显示上次阅读时间失败。这是自动请求之间的冲突，不表示用户刚执行了生成操作。

- 仅为该阅读时间请求启用 `retryBusy`：遇到非重启要求的 409，每 500ms 重试一次，最多重试 30 次；普通 API 的 409 提示保留，401 仍唤起登录，存储交接要求重启时不重试，网络和 500 错误不重试。重试耗尽仍有局部失败反馈。
- 全部／未读内容不等待该写请求，立即开始加载；“本次打开前新增”在基线可靠前不可选，已选此筛选则等待基线。成功后保存基线并恢复选项，迟到响应不得覆盖已恢复阅读状态。
- 未知基线用 `undefined` 表示，JSON 保存时省略，避免维护等待期间刷新将未知状态存成真实首次访问的 `null`；已知 reload 基线在早期渲染前恢复。
- 没有放开任何数据库／文件写入门禁，没有停用自动清理或后台任务。
