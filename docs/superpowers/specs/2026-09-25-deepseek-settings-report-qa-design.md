# DeepSeek 网页设置与报告上下文问答设计

日期：2026-09-25

## 目标与范围

在现有 QQ Digest 网页中加入 DeepSeek API Key 设置，并在每份日报或范围摘要的详情里加入基于该报告原始聊天记录的连续提问。用户已确认：提问入口在报告详情，不在采集列表；问题由用户输入；对话框可追问，但关闭即清空，不保存问答历史。

本次不做全库聊天搜索、向量数据库、跨报告问答，也不在网页修改已配置的 DeepSeek 接口地址和 `deepseek-flash` 模型。原有日报和范围摘要的生成流程继续使用同一个 AI 配置。

## 方案选择

只凭摘要回答速度快，但无法核实细节；把整段聊天无条件发给模型容易超出上下文、增加费用。采用混合方案：仅检索当前报告对应群和日期范围的已归档聊天；预算内发送全部相关窗口，超出预算时按问题检索相关消息并附相邻对话。报告文本帮助定位问题，但原始消息才是事实依据。

## 1. DeepSeek 设置

导航增加“AI 设置”页面，显示当前接口地址、模型、API Key 是否已配置；输入框可保存或替换 Key，不显示旧 Key，也不通过 GET API 返回 Key。页面提供显式的“测试连接”按钮；保存操作本身不访问 DeepSeek。

Key 存在本机项目外的 `D:\Dev\QQDigest\secrets\deepseek-api-key.txt`。这个路径应由 AI 配置字段指定，使源码不依赖单台机器的盘符；当前部署设为上述路径。写入采用同目录临时文件加原子替换，目录和文件限制为当前 Windows 用户及系统管理员可读；权限收紧失败则保存失败并保留旧 Key。Key 不写入项目配置、数据库、日志、错误消息或 Git。网页保存的 Key 优先于旧的环境变量、`ai.api_key_file` 和 codexID 自动发现；不存在时沿用旧解析顺序。下一次 AI 请求立即读取新 Key，无需重启网页服务；定时/命令行任务也使用同一解析规则。

设置接口均要求登录。`GET /api/ai-settings` 只返回非敏感状态；`PUT /api/ai-settings/key` 验证非空单行 Key 后写入；`POST /api/ai-settings/test` 发起最小的 JSON 测试请求，并把认证失败、限流、超时等转换为不含 Key 的友好提示。禁止把 Key 放在 URL 或响应中。

## 2. 报告问答交互

打开报告详情后显示“问 DeepSeek”按钮。点击打开对话框：顶部标明报告群和日期范围，输入框允许提出问题，下方展示本次会话的问答和可展开的来源消息。首次提交前明确提示：为回答问题，会把本报告范围内选中的聊天片段发送到 DeepSeek。提交期间禁用重复发送；关闭或切换报告时清空前端会话状态。浏览器刷新也不恢复会话。

`POST /api/reports/{report_kind}/{report_id}/ask` 接受问题和有限的最近对话轮次，不接受客户端指定的群、日期或原始消息。服务端从报告记录中确定 `group_id`、日期范围和时区，并用左闭右开窗口读取该群的已归档消息。日报只查报告日，范围摘要查其起止日期（含结束日）。不存在的报告返回 404；无原始记录时明确提示无法根据聊天记录核实，不让模型凭摘要编造。

问答服务独立于摘要生成服务。它对用户问题和最近追问做长度/轮数限制，带上报告文本供定位；原始消息在配置的上下文预算内全量使用，超预算时用中英文兼容的词/字片段匹配挑选消息，再加入相邻消息保持语境，并按时间顺序交给模型。每条消息带消息 ID、时间和发送者标识。聊天内容一律作为不可信资料，不能覆盖系统的回答规则。

模型以 JSON 返回回答和引用的消息 ID。后端只接受本次实际提供给模型的 ID，返回其时间和短摘录供页面展示；无可核实证据时要求模型明确表示不确定，不能伪造引用。返回数据包含本次参考消息数及是否发生上下文筛选，便于用户判断答案覆盖范围。追问时前端只提交本次会话的有限历史；服务器不持久化问题、答案或会话。

## 错误、安全与隐私

- 未登录访问设置或问答接口应拒绝；单次问题、历史轮次、消息上下文和模型输出均设上限。
- 缺少 Key、Key 文件不可读、原始消息缺失、DeepSeek 认证失败、限流或超时，都显示可操作提示，不泄露 Key、请求体或完整聊天内容到日志。
- 只向 DeepSeek 发送被问报告对应群与日期范围内、回答所需的消息，不混入其他群；问题和引用在 UI 输出时作为纯文本渲染，防止脚本注入。
- 答案是基于可用归档的辅助解释，不将模型推断冒充群成员的确定结论。

## 验证

先写失败测试，再实现：覆盖 Key 保存与权限/替换/优先级、接口不泄密、设置后新请求生效；日报和范围报告的群/时间隔离、长上下文筛选、连续追问上限、引用 ID 校验、无证据与 API 故障。全套测试通过后，在真实浏览器检查桌面与手机布局、对话框开关和追问、缺 Key 错误及控制台错误。测试中使用假 AI 响应，不发送真实聊天到外部服务。
