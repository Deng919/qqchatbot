## 实测限制与异常记录

1. `nt_msg.db` 解密后的 SQLite 检查报 `database disk image is malformed`，本次未发布该文件。新版 QQ 的文本读取路径使用已成功刷新的 `group_msg_fts.db`，223 条文本采集和去重通过；依赖旧消息库的附件补充路径不能据此判定通过。未更改 QQ 原始库或正式解密缓存。
2. 前两份 AI 输出未得到有效引用，页面按原有逻辑显示“待核实”，未编造来源。重试后的 v3 全部 9 项声明有有效引用，并通过每项关联消息和每个来源的接口校验。引用质量仍依赖 AI 输出，不能表述为每次都稳定返回引用；具体首两次缺失原因未确定。追踪包装器仅配置于验收目录，已恢复原配置。
3. QQ Bot 和自动提醒未开启，未向第三方发送通知。自动任务的覆盖来自既有自动化测试；本次桌面验收不宣称跨日定时任务、全部附件或真实外部通知均已逐项实测。
4. 生产数据没有作为桌面验收写入目标。交付后正式入口指向生产配置，但没有启动生产数据上的自动任务；下次打开桌面快捷方式运行新版。
5. 初始隐藏测试实例与后续窗口连接同一服务，因此先清理初始实例，再对独立拥有服务的窗口验证正常关闭；后者关闭后进程和端口均消失。
6. 更新入口的临时 Python 辅助脚本在入口及版本清单提交后遇到 COM 对象释放错误而退出。随后用独立 PowerShell 读取快捷方式，并用无 COM 的 Python 检查版本清单、包完整性、启动配置、偏好及原文件校验值，全部通过；该异常不是对交付成功的依据。

原有未跟踪的 `.qqdigest-activity.lock`、`qq_digest/web/templates/ai_settings.html`、`qq_digest/web/templates/catchup.html` 和正式配置的 SHA-256 在备份及交付后均保持一致。验收临时开关、群设置、登录凭据和报告不写入正式数据目录。
