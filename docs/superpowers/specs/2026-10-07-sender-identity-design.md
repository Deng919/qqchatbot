# 发送者识别

用户确认补齐发送者，优先本群群名片，其次昵称、QQ 号。当前全文库 40020 保存 UID，归档已有 content_json.sender_uid；原消息页只读 sender_qq，缺少身份映射。

只读本地已解密资料：group_info.db/group_member3（60001 群、1000 UID、1002 QQ、64003 群名片、20002 昵称），profile_info.db/profile_info_v6（1000 UID、1002 QQ、20002 昵称），nt_msg.db/nt_uid_mapping_table（48902 UID、1002 QQ）。群名片按群隔离，冲突 UID 映射不采用。可选资料库缺失或损坏时保留已有 QQ 号，不阻断正文采集。

采集时将发送者名称元数据保存进现有 content_json，不新增表或列。已有归档在本地身份补齐操作中只更新 sender_qq 和对应身份元数据，不改正文、消息 ID、日期、来源引用、同步游标；重复运行幂等。仅能使用已保存 UID 或 QQ 号，不猜发送者。对本机已确认的旧版 40027 群号误存记录，一次性迁移可用全文库中同群、同消息 ID、同时间的记录恢复 UID；无法核实的群号清空，显示未知。通用重复采集在 QQ 冲突时保留原身份，缺 QQ 不清空已有号码。

共享显示辅助函数输出 sender_name，原消息上下文、搜索、消息浏览、候选来源及归档问答使用相同字段。页面安全文本显示“名称 · QQ 号”，缺名称时保留 QQ 号，完全无可用信息才显示未知。名称是本地资料缓存，不声称为发消息时历史名称；合并摘要不指定单一作者。

验证采用合成数据库，覆盖群隔离、资料优先级、UID/QQ 冲突、可选库损坏、旧消息补齐幂等、HTML 形式名称、消息不变及上下文预算。真实资料仅做只读聚合检查和经用户授权的本地元数据补齐，不输出人员名单、不发到 AI。完成后生成新版桌面程序并更新本机入口；公开 GitHub 安装包不自动发布。
