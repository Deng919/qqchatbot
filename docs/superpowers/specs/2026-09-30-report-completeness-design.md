# 摘要完整性提示设计

## 目标

让报告列表、报告详情和总览明确说明摘要覆盖范围。没有足够证据时只显示“无法确认”，不把一份存在的报告等同于完整日报。

## 两层覆盖信息

1. **单群报告输入范围**：读取报告 JSON 中的 `diagnostics`。展示原始归档消息数、实际纳入 AI 的条数；少于 5 条标“样本较少”，上下文截断或预处理丢弃消息时标“部分消息未纳入”。新版报告生成时把这些限制写进 Markdown 的“数据范围”和 JSON 的 `coverage`；日报采集数量与归档数量严重不符时也写入该快照。旧报告没有有效统计时标“范围未知”。
2. **当日跨群覆盖**：使用最近一次对应日期的 `daily_digest` 任务、`job_group_results` 及当日报告记录。显示参与群、失败群、没有报告的群以及报告数；部分成功、任务失败、缺报告均为“有限”。没有任务或逐群结果的旧记录标“无法确认”。当日任务成功也只称“本次已覆盖”，不声称源库历史没有缺口。

报告列表显示短标签，详情展示原因和计数。范围摘要只显示本群输入范围，并说明它只覆盖用户选定的群与日期。总览显示最近日报的跨群覆盖摘要及异常提示，链接到报告或异常页。

## 数据与边界

- 无数据库迁移。单份新版报告的输入限制随原子写入的 JSON/Markdown 保存；跨群结果沿用上一轮持久化的任务与逐群表。
- 旧报告、损坏或缺失的 JSON、旧任务没有逐群结果时不补写历史，也不假设完整。
- “少于 5 条”是提示阈值，不阻止生成，也不把安静群判为采集故障。
- 已知采集失败会阻止该群报告生成，并在同日期的跨群覆盖中列为失败。未知历史缺口仍由后续多群巡检处理。
- 浏览器只用文本节点或转义后的 HTML 展示原因，避免报告数据进入脚本。

## 验证

覆盖低样本、上下文截断、归档数量异常、逐群失败、无消息跳过、旧报告、损坏 JSON、任务缺失、同日期重跑恢复、鉴权与窄屏显示。打包后核对新版模板与 EXE 启动。
