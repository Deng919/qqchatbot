## 正常流程实际操作

独立 Chromium，通过页面控件完成，未使用业务 API 代替这些动作：

1. 登录 → 生成摘要 → 空消息提示 → 更新消息，群和日期保留。
2. 检查缺口显示待补 8 条；更新新增 8 条显示本次补齐；再次更新新增 0 条，不重复宣称补齐。
3. 生成前确认本地 8 条，开始生成后收起面板，实际完成 1 份报告、4 条要点，再打开阅读。
4. 从关联消息查看前后讨论，修改标题和说明后保存知识；知识详情保留真实原文和来源。
5. 查找“乱码”的全部内容，找到摘要、知识、消息；摘要片段无多余标记。
6. 打开搜索原文并收藏，关闭后关键词保留；收藏页能够找回。
7. 查看完整摘要，资源链接显示可读标题和 URL；返回阅读可用。
8. 确认摘要任务的负责人、日期，建立待办并完成，在已完成列表找回。
9. 将资源候选入库、经验候选设为稍后；保存知识列表和稍后列表均正确。
10. 390×620 和 1280×900 检查生成、搜索和完整报告。另准备 41 个启用群及 1 个停用群，
    验证已有多群选择、搜索长列表、勾选、排除停用群、清空后重开不自动重选。

源码测试服务只替换外部刷新边界和 AI 返回：真实采集器读取本轮合成 NTQQ SQLite；AI 仅请求本机模拟服务。
不是针对真实 QQ 刷新、外部厂商 AI、真实通知或真实凭据的验收。
