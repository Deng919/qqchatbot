# QQ 群消息摘要工具设计文档

## 概述

QQ Digest 是一个个人 Windows 工具。它在本地读取 QQ NT 群消息数据库，归档选定群的消息，为每个群生成每日 AI 摘要，通过官方 QQ Bot API 发送摘要，并允许用户确认后再把高价值资源和经验写入 Markdown 知识库。

第一版运行在用户的 Windows 电脑上，同时要求 QQ 客户端保持登录。架构上将采集、归档、摘要、审核和通知分离，便于以后增加服务器部署方案。

## 已确认需求

- 平台：Windows QQ NT 客户端，长期保持在用户电脑上登录。
- 采集：只从复制出来的数据库快照读取本地 QQ 数据库，绝不修改原始 QQ 数据库。
- 首次回填：只回填选定群最近 30 天的消息。
- 增量同步：首次回填后默认每 10 分钟自动刷新数据库并持续采集；使用 60 分钟重叠窗口和消息 ID 去重，避免快照延迟造成漏采。
- 摘要频率：每天一次，默认 22:00。
- 摘要时间窗：可配置；默认覆盖当天 0 点到摘要时刻，也支持切换为“前一天整天”。
- AI 服务：支持任何 OpenAI-compatible Chat Completions API，通过 base URL、API key 和模型名配置。
- 报告：每天生成 Markdown 报告和结构化 JSON 报告。
- 重点信息：AI 只提出候选，必须经用户确认后才写入正式知识库。
- 审核入口：
  - 本地 Web UI，支持 localhost 和局域网访问，必须登录。
  - QQ Bot 指令，仅允许配置的用户 OpenID 使用。
  - 未来可通过 Tailscale 或 ZeroTier 远程访问，不需要重新设计审核服务。
- 知识库：写入用户指定的 Markdown 文件，分别保存资源和可复用经验。
- 群选择：初次通过 Web UI 选择，之后可通过 Web UI 或配置文件持续编辑。
- 部署：第一版本机一体化运行，同时在架构上保留采集端/服务端边界，方便以后部署到服务器。

## 目标

1. 采集选定 QQ 群消息，但不通过第三方协议客户端登录或操作个人 QQ 账号。
2. 生成可靠的每日摘要，区分主题、结论、资源、任务和争议。
3. 保存可能有价值的资源和经验，但不未经确认就污染用户知识库。
4. 当 QQ 私有数据库结构变化时，明确失败并提醒用户。
5. 原始聊天数据保存在本地；只把有长度限制的摘要上下文发送到配置的 AI 服务。

## 非目标

- 不使用 NapCat、Lagrange 或其他第三方 QQ 协议登录。
- 不修改、重新加密或修复原始 QQ 数据库。
- 不做多用户 SaaS。
- 不默认采集无关聊天或所有群。
- 第一版不归档媒体文件本体。
- 第一版不做远程服务器同步。
- Web 审核接口不直接暴露到公网。

## 架构

```text
Windows QQ NT 客户端
        |
        | 正常写入本地加密的 nt_msg.db
        v
QQNT 适配器
        |
        | 复制数据库，提取/使用密钥，只读访问
        v
标准化消息 NormalizedMessage
        |
        v
入库器和 archive.sqlite
        |
        | 每日定时任务
        v
摘要器
        |
        | OpenAI-compatible API
        v
每日报告 + 重点信息候选
        |
        +--> Markdown/JSON 报告
        |
        +--> Web 审核界面
        |
        +--> QQ Bot 私信
        |
        v
确认后的 Markdown 知识条目
```

### 运行目录

```text
qq-digest/
  config/
    config.yaml
  adapters/qqnt/
    数据库发现、兼容性检查、解密和解析
  archive/
    archive.sqlite
  reports/
    YYYY-MM-DD__group.md
    YYYY-MM-DD__group.json
  knowledge/
    resources.md
    experiences.md
  work/
    临时数据库快照；可以安全删除
  logs/
```

源码目录按这些边界组织：

- `collector`：QQ NT 数据库发现、兼容性检查、快照处理和消息标准化。
- `core`：归档、群配置、审核队列、报告生成和知识库写入。
- `ai`：OpenAI-compatible 摘要生成和结构校验。
- `notify`：官方 QQ Bot API 和 WebSocket 指令处理。
- `web`：带登录认证的审核界面和群选择界面。
- `scheduler`：周期采集和每日报告任务。

## QQNT 采集适配器

QQ NT 数据库是私有格式，可能随 QQ 版本变化，因此适配器必须作为显式可替换层存在。

适配器职责：

1. 定位当前活跃 QQ 账号目录和 `nt_msg.db`。
2. 先把加密数据库复制到 `work/`，再进行读取。
3. 从正在运行的 QQ 进程获取数据库密钥，或使用用户显式提供的密钥。
4. 只解密和读取工作副本。
5. 检查必需的表、字段、protobuf 消息体和群标识。
6. 将消息标准化为内部结构。
7. 报告解析质量，不静默接受不可用数据。

原始数据库永远不会以写模式打开。`work/` 是一次性目录；`archive.sqlite` 是持久业务数据库。

开源 QQBackup 系列项目只作为格式和算法参考，不作为稳定运行时依赖。所有对 QQ 版本敏感的逻辑必须留在这个适配器内。

### 标准化消息结构

```text
msg_id
group_id
sender_qq
timestamp
message_type
text
content_json
raw_digest
source_id
device_id
collected_at
```

第一版归档文本，以及链接、文件、回复和转发消息摘要的元数据，不复制图片、视频、音频或文件本体。

## 归档设计

`archive.sqlite` 至少包含：

- `groups`：选定群配置和元数据。
- `messages`：标准化消息，按 `group_id` 和 `msg_id` 去重。
- `sync_state`：每个群的游标和回填状态。
- `reports`：生成报告的元数据和内容指针。
- `candidates`：重点信息审核队列。
- `knowledge_items`：已确认条目及其 Markdown 条目 ID。
- `send_log`：QQ Bot 投递尝试和结果。
- `jobs`：采集、摘要、通知和知识库写入任务状态。

消息默认长期保留。保留策略可以以后增加，但静默删除不属于第一版行为。

## 群选择

初始设置流程：

1. 扫描本地可见的群会话。
2. 显示群名称、群号、最近消息时间和最近 30 天大致消息量。
3. 用户在 Web UI 中选择要采集的群。
4. 将选择结果保存到业务归档库。
5. 只对选中的群执行 30 天回填。

每个群可配置：

- 启用或禁用。
- 是否生成每日摘要。
- 简洁或详细模板。
- 自定义重点关键词。
- 是否提出重点信息候选。
- 采集时间窗。

`archive.sqlite` 中的 `groups` 表是运行时群组配置的最终权威来源。`config.yaml` 的 `groups` 仅用于首次启动或人工批量导入；Web UI 的添加、修改和删除直接持久化到归档库，服务重启后不会被空配置覆盖。

## 每日摘要

默认每日任务在 22:00 运行。

对每个启用摘要的群：

1. 读取配置时间窗内的消息。
2. 过滤明显系统噪声和不可用内容。
3. 提取确定性信息，例如链接、文件名、明确日期和类似 TODO 的表述。
4. 将有长度限制的上下文发送到配置的 OpenAI-compatible 模型。
5. 校验结构化响应。
6. 写入 Markdown 报告和 JSON 表示。
7. 创建状态为 `pending` 的重点信息候选。
8. 将 QQ 通知加入发送队列。

### 报告模板

默认简洁报告包含：

- 群名称和时间窗。
- 主要话题。
- 重要结论。
- 资源和链接。
- 任务或承诺。
- 未解决问题或争议。
- 采集不完整时的数据质量说明。

详细模式额外包含：

- 更完整的话题叙述。
- 关键原始消息引用。
- 有价值时的参与者信息。
- 可选统计数据和值得注意的对话片段。

模板模块可配置，默认仍为简洁模式。

## 重点信息审核

摘要器识别两类候选：

- 资源：网站、教程、工具、仓库、书籍、课程、数据集和文件。
- 经验：可复用方法、排障步骤、配置示例和决策标准。

候选永远不会直接写入正式知识库。每条候选保存：

- 来源群和消息引用。
- 日期。
- 类型。
- 标题。
- 链接或主要内容。
- AI 认为重要的理由。
- 简短原文摘录。
- 状态：`pending`、`confirmed`、`ignored` 或 `later`。

### Web 审核界面

Web UI 监听 localhost 和局域网地址。远程访问应通过 Tailscale 或 ZeroTier 这类私有虚拟网络。

功能：

- 密码登录和会话过期。
- 候选列表，显示类型、日期、来源群、链接、摘录和 AI 理由。
- 按群、日期、类型和状态过滤。
- 查看候选完整详情。
- 操作：确认、忽略、稍后处理。
- 可填写忽略原因，用于以后优化提示词。
- 群选择和单群配置页面。

UI 不接受匿名请求，也不设计为直接暴露到公网。

### QQ Bot 指令审核

官方 QQ Bot WebSocket 接收私信指令。只有配置的用户 OpenID 可以执行。

指令：

- `候选`：列出最近的待审核候选及其编号。
- `入库 12 13`：确认多条候选。
- `忽略 14`：忽略候选。
- `稍后 15`：保留为待审核。
- `查看 12`：查看候选详情。

两个审核入口修改同一个 SQLite 队列，因此状态保持一致。

## 知识库

确认后的条目追加到用户指定的 Markdown 文件。默认文件：

- `knowledge/resources.md`
- `knowledge/experiences.md`

条目格式：

```markdown
## YYYY-MM-DD | 资源
- 来源：群名称
- 标题：示例
- 链接：https://example.com
- 价值：为什么值得保存
- 摘录：简短原始消息摘录
- 报告：reports/YYYY-MM-DD__group.md
- 条目 ID：稳定标识符
```

知识库写入具备幂等性。如果条目 ID 已存在，不会重复追加。

用户可以配置为按类别拆分文件，也可以配置为一个合并文件。长期维护建议使用拆分文件。

## 官方 QQ Bot 集成

QQ Bot 使用官方 QQ 开放平台 API：

- 使用 AppID/AppSecret 获取 access token。
- 通过私信发送每日摘要。
- 通过 WebSocket 接收私信审核指令。
- 只允许白名单用户 OpenID。
- 记录投递状态，并按需重试。

每日摘要会提示待确认重点信息的数量，并附上本地/局域网审核地址。对低频每日一条消息来说，官方主动消息限制预计不是主要瓶颈；但如果投递失败，系统会记录错误并按平台错误码重试。

## 安全设计

- 原始 QQ 数据库只读访问。
- Web UI 必须登录，并支持会话过期。
- 只有配置的 QQ OpenID 可以执行审核指令。
- API key、QQ Bot 密钥和数据库密钥不进入 Git。
- 日志不记录密钥。
- 原始聊天消息不发送给通知服务。
- 只把有长度限制的摘要上下文发送到配置的 AI 服务。
- Web 访问先面向本机和局域网；远程使用应通过私有虚拟网络。

## 兼容性与失败处理

### Doctor 命令

`qq-digest doctor` 检查：

- QQ 进程和版本。
- 数据库位置与可读性。
- 可用磁盘空间。
- 数据库密钥是否可用。
- 必需表和字段结构。
- protobuf 样本解析率。
- 归档数据库连接。
- AI API 连通性。
- QQ Bot 凭据和投递权限。

结果分为通过、警告和阻断三类。

### 失败策略

- QQ 数据库被锁定：等待下一个采集周期重试。
- 密钥提取失败：暂停采集并提醒。
- 数据库结构不兼容：进入 `adapter_incompatible`，停止采集并提醒。
- 解析质量低于阈值：暂停入库并提醒。
- AI 失败：报告保持待生成状态，使用指数退避重试。
- 通知失败：保持 `pending_send`，后续重试。
- 进程重启：根据游标和任务状态恢复，不重复消息、报告或发送。

系统不得把不完整摘要伪装成完整摘要。报告必须包含数据质量说明。

## 服务器部署路径

第一版本机运行。为以后拆分做准备：

- 采集端代码只依赖本机 QQ 环境，输出 `NormalizedMessage`。
- 归档、摘要、审核、知识库和通知代码不依赖 QQ 数据库内部结构。
- 记录中已包含 `source_id` 和 `device_id`。
- 配置文件区分 collector 和 server 部分。
- 未来服务器部署可以让 Windows 采集代理继续运行在 QQ 电脑上，再通过带认证的加密通道同步标准化消息。

第一版不实现同步传输。

## 命令行

主要命令：

- `qq-digest doctor`：运行兼容性和连通性检查。
- `qq-digest sync`：执行一次采集或回填。
- `qq-digest summarize`：为配置的时间窗生成报告。
- `qq-digest notify`：发送待发送通知。
- `qq-digest serve`：运行 Web 审核界面和 QQ Bot 指令监听。
- `qq-digest backfill`：为选定群执行 30 天初始回填。

由 Windows 计划任务或后台服务统一调度周期采集、每日摘要和通知。

## 测试

### 单元测试

- 使用脱敏样本测试 protobuf 和数据行解析。
- 群、发送者、时间戳、文本、链接、文件和回复提取。
- 去重和乱序消息入库。
- 摘要 JSON 结构校验。
- Markdown 知识库幂等写入。
- QQ 指令解析和 OpenID 权限校验。

### 集成测试

- 模拟 QQ 数据库到归档库的完整流水线。
- 回填和增量游标行为。
- 报告生成和候选创建。
- Web 审核状态流转。
- QQ 指令审核状态流转。
- AI、通知、数据库锁定和进程重启后的失败恢复。

### 端到端验收

- `doctor` 在用户真实 Windows QQ 环境中通过。
- 选定群最近 30 天消息完成归档，抽样数量和内容与 QQ 显示一致。
- 每天 22:00 自动生成摘要。
- QQ 私信通知成功送达。
- 同一局域网中的手机浏览器可以登录并确认候选。
- QQ 指令可以列出并确认候选。
- QQ 版本或数据库结构变化会停止采集并提醒，而不是存入错误数据。

## 验收标准

1. 用户可以在 Web UI 中选择群，并可以通过配置文件编辑。
2. 首次设置时，工具归档选定群最近 30 天消息。
3. QQ 保持登录时，工具持续增量采集。
4. 工具每天 22:00 为每个启用群生成一份简洁日报。
5. 工具通过官方 QQ Bot 把摘要发送给用户。
6. 工具将重要资源和经验提取为待审核候选。
7. 用户可以通过 Web UI 或 QQ 指令确认候选。
8. 确认条目在配置的 Markdown 知识文件中只出现一次。
9. QQ 数据库保持未被修改。
10. 适配器失败可见、可恢复，不会静默污染归档。
