# QQ Digest 顶部导航 UI 优化设计

## 目标

在不修改采集、摘要、候选审核和通知业务逻辑的前提下，统一五个工作页面的视觉层级和交互状态，提高桌面端数据浏览效率，并让手机端可以快速查看状态和审核候选。

设计定位：个人使用的本地数据工作台，强调安静、清晰、可靠，不采用营销页布局、渐变背景、装饰性大卡片或高强度动画。

## 设计方向

采用用户选定的“顶部导航数据台”方案：

- 深色顶部栏承载品牌和五个全局入口。
- 页面标题、主要操作和筛选条件放在独立的页面工具栏中。
- 内容区域最大宽度为 1440px，在宽屏居中。
- 保留白色内容表面、浅灰背景和青绿色主色，统一边框、状态色、字号和间距。
- 数字使用等宽或 tabular figures，便于比较消息量和时间。

## 桌面布局

顶部栏固定在视口顶部，高度约 52px。品牌位于左侧，导航位于右侧；当前页面通过底部强调线和高对比文字表示，不使用大面积圆角选中块。

页面工具栏位于顶部栏下方，包含页面标题和当前页面的主要操作。筛选条件较多时放在内容区内的紧凑工具条，不把所有输入框挤入页面标题栏。

数据区使用以下结构：

- 总览：四项连续指标、自动任务表、群组活跃度表。
- 群组：配置表，首列在桌面可保持可见，表格自身横向滚动。
- 采集：状态与控制区在前，消息流在后，时间、发送者、类型和正文层级明确。
- 摘要：日期与群筛选置于工具条，摘要列表采用紧凑行或分段内容。
- 审核：筛选工具条、候选列表和右侧详情抽屉；按钮按主次排列。

## 手机布局

品牌栏保持单行，导航成为其下方可横向滚动的标签栏，不折行、不遮挡内容。

- 总览表格转换为纵向任务条目，每条显示名称、状态、最近执行时间和计划。
- 候选卡片保持单列，主要审核按钮使用稳定尺寸并允许换行排列。
- 群组配置保留局部横向滚动，因为强行压缩全部字段会降低可操作性。
- 页面工具栏改为纵向布局，搜索框和筛选器占满可用宽度。
- 页面本身不得产生横向滚动；只有明确的表格容器可以横向滚动。

## 基础组件

基础样式集中在 `base.html`，页面模板只保留页面特有规则：

- 顶部导航、页面工具栏、内容容器。
- 按钮、输入框、选择器、开关和焦点状态。
- 指标带、状态徽标、数据表、列表和空状态。
- Toast 成功与失败反馈。
- 候选详情抽屉和移动端遮罩。

交互动画限定为 120 到 200ms 的颜色、透明度和位移变化，并遵守 `prefers-reduced-motion`。

## 状态与错误

- 加载中：操作按钮禁用并显示明确的进行中文案，避免重复提交。
- 空数据：说明当前为什么为空，并保留相关操作入口。
- 失败：使用页面内状态行或 Toast 显示后端错误，不使用 `alert()`。
- 任务错误：保留原始错误的安全转义和截断展示，完整文本通过标题提示查看。
- 登录失效：继续统一跳转到登录页。

## 可访问性

- 保留跳到主要内容链接和 `aria-current`。
- 所有输入控件具有可访问名称，键盘焦点清晰可见。
- 文字和状态颜色达到可读对比度，不仅依靠颜色表达状态。
- 触控操作目标至少约 36px，高频移动端按钮优先达到 40px。

## 不在本轮范围

- 不引入 React、Vue、Tailwind 或第三方组件库。
- 不修改任何 API、数据库结构或调度逻辑。
- 不增加暗色模式、主题切换、图表库或复杂动画。
- 不重构候选审核的业务状态机。

## 验收标准

1. 五个页面使用统一的顶部导航和页面工具栏。
2. 1440×900 下主要信息完整、无重叠，内容区不松散。
3. 390×844 下页面无整体横向溢出，导航和表格局部滚动可用。
4. 总览任务在手机端转换为列表式信息布局。
5. 群组关键词、采集窗口、开关和删除操作保持可用。
6. 候选筛选、查看、确认、忽略、稍后操作保持可用。
7. 页面控制台无错误，现有后端和 Web 测试全部通过。
