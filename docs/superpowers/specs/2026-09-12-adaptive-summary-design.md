# 自适应摘要设计

## 目标

取消面向用户的“精简/详细”模板选择，改为单一的自适应摘要流程。摘要长度由有效消息数量、话题数量和讨论深度决定：信息少时保持简洁，信息多时充分覆盖，但不得用闲聊或重复内容凑篇幅。

历史报告及其中记录的模板值不要求迁移或重新解释。现有数据可以继续留在归档中，但不影响新摘要的生成逻辑。

## 报告结构

新摘要固定使用以下结构：

1. 今日概览：2–4 句，概括当天讨论重心、主要进展和整体状态。
2. 主要话题：通常 3–8 个；每个话题包含背景、主要观点、结论或当前状态。信息充分时约 80–150 字，信息不足时按实际内容缩短。
3. 重要结论：只记录明确达成的判断、决定或已验证结果。
4. 资源与链接：记录标题、链接和用途或群内评价。
5. 任务或承诺：记录执行人、事项和消息中明确出现的期限。
6. 未解决问题或争议：记录仍待确认的问题和存在分歧的观点。
7. 确定性提取与数据质量：继续由程序生成，保留现有行为。

不新增“金句”栏目，以免报告退化为聊天摘录。

## 自适应规则

- 对话形成两条及以上有信息量的往来时，可以识别为话题，不再统一要求五条相关消息。
- 一条独立但信息完整的消息可以进入资源、任务或未解决问题；只有在其本身构成完整公告、结论或重要事件时才可形成话题。
- 每个话题尽量覆盖“讨论什么、有哪些关键观点、最后得到什么结果”；参与者归属明确时可在摘要中注明，但不得猜测。
- 多个相近消息合并，同一事实不在概览、话题和结论中机械重复。
- 纯闲聊、表情回应、无上下文片段和系统通知不用于扩充篇幅。
- 没有实质内容时允许生成简短报告或空话题列表，不能为了满足数量目标编造内容。

## 程序改动

- 摘要模型新增可选的 `overview` 字段，旧式或异常响应缺失该字段时按空字符串处理。
- Prompt 组装器移除模板参数和两套长度限制，改为单一的结构说明与自适应覆盖规则。
- 群配置、群组管理页面、日报流程和范围摘要页面不再提供模板选择。
- 日报与范围摘要统一调用同一个自适应 Summarizer。
- 新报告不再展示模板标签。旧报告无需迁移；读取旧记录时忽略已有模板字段。
- 为避免一次性破坏旧配置文件或旧客户端请求，解析层可以接受但忽略遗留的 `template`/`detail_mode` 值；新界面和新响应不再暴露这些概念。

## 数据流与失败处理

采集和清洗后的消息仍按群分类进入 Summarizer。模型返回结构化 JSON，经校验后渲染为 Markdown 并写入归档。新增字段采用向后兼容默认值；非法 JSON、群 ID 不匹配和字段类型错误仍按现有机制失败并记录，不通过静默填充掩盖模型错误。

摘要输入指纹将使用新的自适应 Prompt，因此同一批消息在升级后会被识别为新的生成输入。历史报告不主动删除。

## 验证

- 单元测试覆盖自适应 Prompt、`overview` 的解析与缺省、Markdown 渲染以及移除模板后的请求校验。
- 回归测试覆盖日报、范围摘要、报告归档和旧配置兼容。
- 使用当天真实归档消息重新生成五个群的摘要，检查空摘要比例、话题覆盖、重复内容和事实归属。
- 在真实浏览器中确认群组页、范围摘要页和报告页不再出现模板选择或模板列，并验证报告详情正确显示“今日概览”。
