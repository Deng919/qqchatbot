## 依据与范围

`D:\Cache\QQDigestWorkflowTrial-20261017`。用户要求继续并已授权不重复询问日常实施选择。

## 方案选择

优先改现有展示逻辑。重算更新后缺口需要再次读取源库，且本次问题实际来自阶段文案，故不增加采集步骤；
引入完整 Markdown 库会扩大依赖和渲染范围，本次只清理现有摘要展示片段；生成面板保留共享选群器，避免再造组件。

### U01 更新与检查分开表述

共享结果渲染器依据已提交的 `payload.dry_run` 判断阶段。检查结果显示“待补缺口”，成功更新显示“本次补齐”。
失败结果不得宣称补齐成功。现有接口字段、计数、重试时冻结的日期与群集合均保持原语义。

### U02 摘要搜索片段可读

仅在报告搜索的展示片段中清理标题、列表、加粗、行内代码定界符及系统原消息引用标记。
Markdown 链接显示为标题和可读 URL，保留正文、代码内容、普通乘号和下划线。匹配、总数、排序、分页、报告文件和来源数据不变。
聊天消息与知识条目的原文片段不套用报告清理规则。
完整摘要的已有安全文本渲染器同样把 Markdown 链接转为可读文字和 URL，不引入 HTML 渲染；代码块保持逐字内容。

### U03 生成面板减少滚动

移除 `range-group-list` 的外层高度限制和滚动容器，保留共享选群器对长群列表的边界限制。
首次进入时若仅有一个启用群且没有明确的其他选择，默认选中该群；已有单群或多群选择保持。
有明确选择时默认收起选群器，未选群时展开；显式空选择 `__empty__` 不自动填回。
用户主动清空后不在重绘、重开或异步更新中重新替其选择。范围、数量预览、在途状态与日期保留逻辑维持现状。
