# 多 AI 接入与用途切换设计

## 目标
在不破坏现有 DeepSeek／本机桥接配置的前提下，允许用户配置多个 OpenAI 兼容接口，并为摘要、报告问答、归档问答和附件识图分别选择连接。

## 方案
在 `ai` 配置下增加 `connections` 与 `purpose_connections`。每个连接包含稳定 id、显示名称、兼容接口地址、模型、密钥环境变量或本地密钥文件、JSON 模式和识图能力。现有顶层 `base_url`、`model`、`ui_api_key_file` 等字段继续作为 legacy 连接读取，避免已有 YAML 迁移失败；没有新增连接时完全沿用当前 provider_priority／桥接逻辑。

用途解析集中在 AI factory：summary、report_qa、archive_qa 和 vision 读取对应连接。兼容连接使用现有 `AIClient`，桥接只允许 legacy 开发版路径；连接未配置、密钥缺失或公开版策略不允许时，在调用前明确失败，不自动借用其他用途连接。

## 设置与安全
`/api/ai-settings` 返回连接的非敏感元数据、当前用途选择和密钥是否已配置，不返回密钥。新增保存连接、删除连接、选择用途和测试连接接口，均使用配置文件的原子保存、版本校验和现有 `setup_mutation` 互斥。密钥沿用现有受限权限文件。公开版继续限制为官方 DeepSeek 配置；本机桥接仅开发版保留。

## 验收
覆盖旧配置兼容、多个连接选择、用途映射、未知连接拒绝、密钥隔离、配置原子更新、设置 API 鉴权／冲突、测试使用所选连接，以及摘要／问答／识图不会错用连接。运行全量 Python 和已有 CJS 检查。
