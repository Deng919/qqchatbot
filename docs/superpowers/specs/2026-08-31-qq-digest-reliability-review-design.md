# QQ Digest 可靠性与审核闭环设计

## 目标

在不重建现有归档的前提下完成四项能力：稳定数据库快照、完整候选审核、可配置 Markdown 目标、AI 与通知自动重试。

## 稳定数据库快照

- 解密前将每个加密数据库复制到 `work/snapshots/<run-id>/`。
- 复制前后比较源文件大小和纳秒修改时间；复制期间发生变化则删除副本并重试，最多三次。
- 解密器只读取快照，不读取 QQ 正在写入的源文件。
- 当前采集路径使用的核心库必须具备必需表且 `PRAGMA quick_check` 返回 `ok`：存在全文库时要求 `group_info.db` 与 `group_msg_fts.db`，旧版无全文库时要求 `group_info.db` 与 `nt_msg.db`。未被当前采集路径使用的损坏历史库保留旧输出并告警，不阻止全文库刷新。
- 所有核心文件均验证成功后才替换输出文件；单文件失败保留上一份输出。
- 任务结束删除本次快照目录，异常退出遗留目录可安全删除。

## 候选审核

- 提供候选 JSON API，支持 `status`、`group_id`、`type`、`date_from`、`date_to` 和 `q` 过滤。
- 状态支持 `pending`、`later`、`confirmed`、`ignored` 和 `all`。
- 提供候选详情 API，返回来源消息引用、完整内容、忽略原因和更新时间。
- 审核页面使用状态页签和筛选控件；“稍后”页面允许恢复为待审核、确认或忽略。
- 现有表结构保持兼容，不删除任何候选。

## Markdown 路径

- 新增 `knowledge.resource_path` 与 `knowledge.experience_path`。
- 相对路径相对于项目数据目录解析；绝对路径按原值使用。
- 未配置时继续使用 `knowledge/resources.md` 和 `knowledge/experiences.md`。
- Web 与 QQ Bot 共享同一 `KnowledgeWriter` 和归档记录逻辑。

## 自动重试

- AI 请求仅对网络错误、HTTP 408、429 和 5xx 重试；其他 4xx、无效 JSON 和结构错误立即失败。
- AI 重试次数和基础延迟通过配置控制，并遵守 `Retry-After`。
- 日报失败后记录失败任务，当天按配置间隔自动重试，达到上限后停止并保留可见错误。
- 通知先写入 `send_log` 队列，状态为 `pending_send`；发送失败写入重试次数、下次执行时间和错误，后台周期处理到期项目。
- 队列记录包含报告、接收者和发送所需载荷；成功状态为 `success`，不可重试失败为 `failed`。

## 数据迁移

- `send_log` 通过增量 `ALTER TABLE` 添加接收者、载荷、重试次数、下次执行时间和更新时间。
- 旧记录保持原状态，不自动重新发送。
- 新配置均有默认值，现有 `config.yaml` 可直接加载。

## 验收

- 快照源变化时不会替换现有解密库。
- 当前采集路径的核心解密库完整性检查通过。
- 候选四种状态均可查看、过滤和恢复。
- 自定义绝对/相对 Markdown 路径均可写入且幂等。
- AI 429 和通知临时失败按策略重试，永久失败不会无限循环。
- 全量测试、编译检查、真实数据库刷新和桌面/手机宽度 UI 检查通过。
