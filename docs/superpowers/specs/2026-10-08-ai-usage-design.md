# P2-06 AI 用量与调用上限设计

## 目标与方案选择

图片、扫描 PDF、摘要和问答都可能产生付费请求。目前客户端会自动重试，但没有统一计数，且读取响应时未保留服务方返回的 usage。

推荐本轮先做「用量统计＋月度调用上限」：计数容易核实，能直接挡住额外请求，不依赖价格和图片 token 的预测。仅显示统计不能控制自动重试；直接按人民币硬拦截需要预估图片与输出用量，误差较大。费用仍提供估算，但本轮不承诺账单金额硬上限。

## 用户行为

- 放在已有「设置 → AI 连接」中，不增加常驻导航或独立功能开关。
- 显示本月已发起次数、成功／失败／结果未知、已知输入与输出 token、缺少 usage 的次数及费用估算。
- 可设置月度最多调用次数，0 表示不限；默认不限，不擅自暂停已有自动任务。限制按照配置时区的自然月计算，修改时区不抹掉历史记录。
- 可按接口来源和模型填写每百万 token 单价：输入缓存命中、未命中、输出。空值表示未知；不填默认价格，不把未知费用显示为 0。历史请求保留发生时的费率快照，修改费率不改过去的估算。
- 每一次实际 HTTP 尝试都算一次，包括自动重试、无效 JSON 后的重试和连接测试。缓存命中、本地文件正文提取及限额拦截不计调用。
- 达到上限时提示「本月 AI 调用已达上限，可调整上限或下月继续」。新付费调用停止，采集、查找、已有摘要和本地文件提取继续。
- 附件因限额暂停显示明确状态；下月或上限调高后可继续读取，不当作永久失败。已经读过的图片内容仍可使用。

## 接入范围与模块

- 新 `ai_usage.py` 服务管理设置、记录和统计；新 `web/ai_usage_routes.py` 提供鉴权接口，主程序只负责组装。新增表放在现有归档 SQLite 内，随现有备份／恢复迁移。
- 在 `AIClient` 的每次 HTTP 尝试前统一预占次数，响应后保存 usage 和结果；保留 `chat()` 返回业务 JSON 的契约。
- `ai/factory.py` 及所有直接创建 API 客户端的路径接入同一服务：网页／CLI 日报、范围摘要、重新生成、摘要问答、归档问答、图片与扫描页面读取、首次设置连接测试和 AI 设置连接测试。
- 开发专用的本机桥接不计入付费 API 次数，不改公开版仅 DeepSeek 的限制。统计页面注明「API 调用」，不声称代表所有模型活动。
- 统计只保存时间、用途、模型、接口来源、结果分类、token 和费率；不保存聊天正文、文件内容、密钥、原始响应或完整错误正文。

## 并发、失败与兼容

- 用专用 SQLite 连接和原子事务预占额度，避免复用业务的共享连接；多窗口、多线程和 CLI 同时运行时不突破调用上限。
- 预占提交之后才发 HTTP；超限不发网络请求，也不进入自动重试。限额错误作为明确终止原因传播，不触发新的付费备用请求。
- 网络中断、进程退出及未提供 usage 的结果保守计入次数，token／费用标为未知，不猜测为零。仍在处理的请求显示处理中，不提前判成失败；结束时再记录结果。
- 响应可计费但业务 JSON 无效的请求保存为失败，仍记录其有效 usage。重试分别记账。
- 接口接收严格非负整数上限与十进制费率；多窗口保存设置采用版本校验。被拒绝的保存不会覆盖原设置。
- 不重置现有配置、群权限、阅读状态或附件缓存。旧归档首次使用新增空账本，旧请求不补造用量。

## 验收标准

1. 模拟传输证明第 N 次获准、第 N+1 次不发 HTTP；自动重试、连接测试和图片走相同限制。
2. 并发争抢最后一个额度最多发一条请求；重启后计数不丢失，月边界与修改时区不绕过限额。
3. 成功、HTTP 错误、网络异常、无效业务 JSON、usage 缺失和格式异常都正确分类，未知不作零。
4. 关闭限额保持现有业务行为；达到上限后采集和本地文件提取仍正常。
5. 费率快照、缓存命中／未命中口径、备份恢复和设置版本冲突有针对性回归。
6. 用独立合成配置验收宽窄屏设置保存、统计与限额提示；不调用真实 QQ 或 AI。
7. 相关及全量测试、独立审查、包内模块／模板核对通过后，更新本机桌面入口，保留 Compact 回退版。公开安装包不自动发布。
