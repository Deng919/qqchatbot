# 任务与待办收件箱设计

## 目标

将有原消息证据的日报任务变成可人工确认的待办，并允许从搜索到的原消息直接创建待办。确认后可编辑内容、负责人、准确的截止日期和状态；到期事项在程序内醒目提示。

## 方案

比较过自动写入待办、独立候选审核和沿用知识候选三种方式。采用独立的任务收件箱：日报任务只生成待确认建议，不自动成为正式待办；知识候选的数据模型和处理动作与待办不同，不复用它的表。这样用户能先核对行动承诺和来源，再决定是否跟踪。

## 数据与来源

- 新建 `tasks` 表，保存标题、负责人、ISO 截止日期、状态（进行中／已完成／已取消）、群 ID、原消息 ID 列表、来源报告 ID、创建和更新时间。第一条原消息以复合外键关联消息表，防止并发删除群时留下无来源任务；来源字段创建后不可编辑。
- 新建 `task_suggestion_decisions` 表，记录已确认或已忽略的建议指纹，避免页面重复出现已处理建议。
- 建议只取最近 30 天日报 `tasks` 栏，并要求 `evidence_version=1` 且至少一条通过现有同群、同日报日期验证的消息引用。旧报告和无有效引用的项目不进入建议列表，页面说明这个范围。
- 指纹由报告 ID、任务字段（包括原始截止描述）和已验证来源构成。报告内容变化可形成新建议；已确认任务保留创建时的快照和原消息链接。
- 从消息直接创建时，后端验证 `(group_id, msg_id)` 确实存在。任何任务必须至少保留一个有效原消息 ID，不接受纯文本无来源任务。
- AI 的自然语言 `deadline` 只显示作参考；只有用户选择精确日期后才存入截止日期。

## 界面与流程

- 新增“待办”页。上方显示待确认建议、进行中、今天到期和逾期数量；两个分页分别为“待确认”和“我的待办”。
- 建议可查看原消息上下文，填写／修改标题、负责人、截止日期后确认，或忽略。
- 正式待办支持编辑、标为完成、取消和重新打开；保留来源按钮与报告链接。默认优先显示逾期和临近到期项，并可筛选状态。
- 搜索结果的消息卡片提供“加入待办”，预填消息内容，用户确认后创建。到期提醒先在应用内的待办页及总览入口显示；系统级通知留给路线图 P1-05 的提醒规则。

## 错误与验证

所有 API 要求登录。无效日期、空标题、错误状态、伪造建议键、跨群或不存在的消息均返回明确错误；更新不改变来源。数据库迁移在现有归档初始化中执行。测试覆盖候选校验、确认去重、消息创建、编辑与状态转换、到期分类、鉴权，并在真实浏览器检查桌面与窄屏交互。
