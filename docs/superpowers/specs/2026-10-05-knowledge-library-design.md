# 知识库入口与原消息保存

用户已确认：知识库始终可查看，候选审核单独开关，原消息提供保存按钮。

## 使用流程

四个主入口保持摘要、查找、群聊、设置；查找下增加“关键词查找／知识库”两项。知识库默认展示全部已入库资源与经验，可按群、类型、关键词分页筛选，打开全文及来源。摘要的更多工具也有知识库入口。审核关闭只影响候选整理，既有知识可读、人工选中的原消息可保存。待确认内容不会被自动批准。

原消息查看组件在引用消息旁显示“保存到知识库”。弹出表单填写标题、资源或经验分类、可选说明与链接，显示原文。后端从本地归档读取原文和群号，不接受客户端伪造原文；保留全部原文和来源消息 ID。重复保存同群同消息同分类复用已有已入库条目，不覆盖用户旧标题。写入失败恢复 Markdown 和数据库；在冲突后台任务执行时明确要求稍后重试。

## 数据和模块

复用 candidates 与 knowledge_items 和原 Markdown 文件，无格式迁移。独立 knowledge_library.py 处理查询、保存和确认；web/knowledge_routes.py 注册认证接口与页面。页面和共用保存表单分为独立模板，搜索知识链接改为知识详情，关闭审核也能打开。旧候选确认改用同一保存服务，旧撤销仍遵守审核开关。

## 验收

旧知识无需关键词即可看到；关闭审核仍可浏览详情；待审核记录不能经知识详情或来源接口读取；人工保存跨群同 ID 校验、去重、分页、全文及来源、失败回滚均有测试。浏览器覆盖消息保存、刷新知识库、返回来源、开关及窄窗口，独立复审后打包更新桌面入口和仓库。
