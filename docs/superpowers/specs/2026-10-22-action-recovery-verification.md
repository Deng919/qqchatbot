# 连续操作与刷新失败恢复

## 复现事实

用户报告二手“不感兴趣”点两次后无法继续操作。正常网络下连续隐藏八个商品未复现；在第二次保存成功后注入列表 GET 503，可稳定复现旧卡片留下、按钮永久 disabled。没有用户当时的请求日志，不能据此断言当时一定发生了同一个网络错误；本次修复针对已复现的失效路径。

进一步检查发现：隐藏保存期间另一次列表刷新可能生成同商品的新卡片，只删除原按钮所属旧节点会留下新卡片；解除屏蔽和恢复显示也可能在刷新失败后保留旧操作。提醒规则刷新失败会留下旧 revision；目标话题列表失败后，选择有效建议仍不能提交；旧阅读模式保存已读状态后依赖后台刷新才能恢复按钮。

## 修复

- 隐藏保存成功即移除所选商品当前卡片／发布记录，按钮通过 finally 恢复；商品卡和发布记录使用稳定商品 ID，覆盖保存期间发生的重绘。推广聚合卡不使用成员商品 ID，保留其他商品。
- 将操作保存和列表刷新分开反馈；列表读取失败提供重试，已保存操作保持成功提示。恢复显示、解除屏蔽成功后移除对应旧行；名单读取失败可直接重试。
- 提醒列表及规则刷新失败时移除失效的操作卡并提供重试，避免继续提交旧 revision。
- 选择有效话题建议时恢复选择框和提交按钮，并使尚未完成的目标列表响应失效，避免覆盖用户选择。
- 已读保存成功后立即重绘当前详情，旧阅读模式也不依赖列表刷新恢复操作。
