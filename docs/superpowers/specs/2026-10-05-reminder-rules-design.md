# P1-05 提醒规则设计

日期：2026-10-05。状态：用户要求按路线图继续，并选择推荐的程序内＋Windows 通知；按该方案实施。

## 范围与取舍

推荐复用本地归档建立持久提醒规则、程序内提醒列表和 Windows 桌面横幅。相比只用网页提醒，它可以在窗口不在前台时提醒；相比立即扩展更多外部渠道，当前方案与用户选择一致，测试可以完全使用合成数据。现有 QQ 日报通知继续沿用既有流程，P1-05 本轮提供程序内及 Windows 两个可选渠道。

四种规则为关键词命中、新资源候选、待办到期、运行故障。每条可命名、启停、选择全部／指定群，选择程序内／Windows，配置关键词和免打扰时段。独立 reminders 开关默认关闭；程序运行期间每 60 秒检测，关闭功能暂停检测与投递。入口为设置下的提醒规则页面，保留四个主入口。

## 事件与去重

新建或重新启用规则记录消息 rowid、候选 ID、任务／故障检测时间基线，历史聊天及资源不补发。关键词对归档消息正文做 NFKC／大小写规范化后字面任一命中，空正文跳过；每次最多处理 200 条并推进到实际处理位置，不跨过剩余项。新资源来自非忽略的 resource 候选；同群相同非空链接视为同一事件，无链接按候选编号区分。已启用规则修改条件后仅处理修改后的新增消息和资源。

待办按配置时区的自然日判断：未完成且截止日不晚于今天，首次符合时提醒一次；创建规则时当前到期未完成任务也可提醒。任务 ID＋截止日构成事件键，改期形成新事件；重复扫描／重启／取消后重新打开不对同一截止日轰炸。投递前再次检查任务是否仍到期，完成、取消、改期后的旧排队提醒取消。

故障读取持久 jobs、sync_state 和失败通知，排除已经恢复的内容。只提醒规则启用后新增／更新的故障；相同群、类型、日期、阶段及原因构成同一事件，自动重试的新任务 ID 不造成重复。故障详情指向已有运行记录／异常页，提醒文本不复制可能含凭证的底层错误。限制群范围的规则不把范围未知的全局故障猜成选定群。

SQLite 保存规则、独立扫描游标、提醒事件、已读状态和渠道投递状态；唯一约束为 rule_id＋event_key，规则修改不清空历史去重。删除规则用停用／软删除保存去重历史，删除群清理该群提醒。备份恢复包含新增表，无新增绝对来源路径。

## 免打扰与通知

时间按现有摘要时区，HH:MM；支持跨午夜，起止相同表示不启用免打扰。免打扰覆盖程序内发布与 Windows 投递，符合条件的事件持久排队，结束后继续并先核实任务／故障是否仍有效。已有提醒在免打扰期间仍能阅读。

Windows 只在桌面程序可用，纯浏览器服务显示渠道不可用并保留排队，不把它当成已投递。每个周期最多一条汇总横幅，正文只显示规则名称及计数，引导到提醒列表。使用 Shell_NotifyIconW 系统接口，发送成功仅表示 Windows 接受请求；系统免打扰／通知设置仍可能抑制显示。接口失败最多三次有界退避并记录原因，保持程序内内容可查看。崩溃后已经提交到系统但未写成功的状态按“未知”保留，避免自动重复轰炸；可由用户明确重试。

## 预览、网页及边界

规则保存前可用当前本地数据预览最近命中例子、群、来源、免打扰状态及渠道可用性。预览不写规则、游标、事件或投递状态，不触发 Windows 或任何外部发送。明确预览可包含历史示例，实际规则从保存基线开始。规则更改使用 revision，旧窗口返回 409 并保留输入；分页、筛选和已读只修改自己的提醒。

独立业务服务、路由、后台循环与 Windows 适配器；网页仅组装。工作连接独立，操作锁覆盖规则／事件写入以及存储迁移、备份、群删除等；取消网页请求不释放运行中的操作。功能关闭、规则停用以及去掉 Windows 渠道后未投递项停止发送；不会把已送通知变成未送。

## 验收

真实 SQLite 测试四种来源、启用基线、任一关键词、群边界、资源去重、任务时区／改期／完成、故障重试聚合、重启去重、免打扰跨日、分页、事务及备份恢复。投递用可注入 sink 验证请求次数、失败与未知状态；Win32 验证适配器结构和资源释放。接口验证鉴权、功能关闭、越界输入、并发冲突。JavaScript 验证延迟响应／重复提交／预览作废和失败保留输入；真实浏览器宽窄屏保存、预览、已读与分页。最终全量测试、独立复审和桌面包合成启动通过才勾选路线图。
