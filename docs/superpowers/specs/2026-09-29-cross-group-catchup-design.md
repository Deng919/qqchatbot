# 跨群补看设计（P1-01）

## 目标

在一个页面汇总各群**已生成的日报**中的主要话题、结论、资源、任务和未解决问题。提供“上次查看后”“今天”“最近七天”三个范围、逐条已读状态、完整报告入口和原消息上下文入口。页面不会自动生成摘要或调用 AI。

## 数据与边界

- 只使用 `reports` 日报，避免范围摘要和日报重复。报告 JSON 缺失或损坏时跳过并给出数量提示。
- 新报告沿用 `report_sources` 的引用验证：仅展示同群、同报告日期的实际归档消息 ID。没有有效引用显示“待核实”。旧版无逐条证据的报告显示“旧报告无逐条来源”，仍可打开完整报告。
- 每条卡片使用报告 ID、条目类别、内容和来源 ID 的哈希作为稳定键。报告内容变更后成为新的未读条目。
- SQLite 新增 `catchup_state`（单用户最近打开时间）和 `catchup_reads`（条目键、已读时间），随现有数据库备份恢复，不改变报告 JSON。
- 打开补看页时记录本次打开时间，并返回上次打开时间；首次打开的“上次查看后”显示最近七天。切换筛选不改变本次比较基准。
- 服务端分页，每页 30 条。所有接口沿用当前登录校验；已读写入只接受 64 位十六进制键和布尔值。

## 界面

导航新增“补看”。顶部提供三个范围切换和总条目、未读数量。卡片展示日期、群、类别、要点、来源状态、已读按钮及完整报告链接。点击来源在页内展示该消息前后文；空状态解释需要先生成日报。窄屏改为单列，不依赖横向滚动。

## 验收

单元测试覆盖时间范围、跨群排序、旧报告、引用缺失、已读持久化、报告改写后重新未读。接口测试覆盖登录、参数校验和来源跳转。浏览器检查桌面及窄屏筛选、已读和来源交互。完整测试通过后重建 Windows EXE 并更新桌面快捷方式。
