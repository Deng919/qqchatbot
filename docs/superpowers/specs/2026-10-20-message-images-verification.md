# 消息图片展示与识别

## 需求与实现

在原消息正文下显示可核实的本地原图与识别文字，复用现有附件读取和缓存。通用上下文用于摘要来源、检索、收藏和二手来源；二手弹窗不再另外把图片放在全部消息上方。

- 浏览图片不调用 AI。首次识别可点击“开启本群识别并读取”，明确打开该群的图片读取开关；已有开关保持原值，未批量开启任何群。
- 原图通过登录后的同群、同消息、同附件接口取得，验证 MD5、文件类型、大小及路径；不返回本地路径，不请求消息中的外部图片 URL。原图使用 `no-store`、`nosniff`。
- 转发子消息沿用带路径的附件键；二手群的屏蔽账号在图片展示、原图读取和识别之前过滤。
- 识别复用 `message_attachments`，原消息正文保持不变。成功结果优先使用缓存；失败可以再次读取。识别文字使用文本节点展示。
- 项目原文字桥接不能接收内容块；有图片的请求改用同安装目录已有的 `invoke-pool-mcp.ps1`，通过 stdin 传入内嵌图片。保留现有账号池锁、清理和当前账号目录；未修改全局桥接工具或读取凭据内容。缺少多模态入口时报告配置错误，不丢弃图片伪装成文字识别。
- 明确配置的 vision 连接优先；当前桥接优先配置也能用于图片。原有兼容接口模式保留。

## 实机边界

当前生产归档里没有可核实的 image 类型附件引用，最近一周也未发现这类引用；只读检查本地原消息库时，全表读取发生 SQLite DatabaseError。该证据不能证明所有图片文件都不存在，也不能将缺失引用直接当作“尚未下载”。本次实现和真实桥接识别已分别验证，但不能宣称当前所有历史图片都已恢复或识别。

只有取得对应消息的完整图片引用，并且原文件存在且通过校验后，才会展示原图、送入识别。未使用 NapCat、未要求重新登录 QQ、未操控或关闭 Codex 浏览器。
