# 按群读取图片与文件

用户已选择开启后自动加入摘要和问答。

群聊详情增加“读取图片”“读取文件”，默认关闭且分别保存。开启时说明选中群附件内容会发送给 DeepSeek；后台不为其他群解析附件。读取结果单独缓存，保留原消息正文，引用仍指向同群原消息。

图片使用 DeepSeek Flash 多模态输入，支持 JPEG/PNG/GIF/WebP，覆盖截图文字、照片和图表。文件本地提取 PDF、DOCX、XLSX、PPTX、TXT/MD/CSV/JSON/LOG 正文；Office 内嵌图片暂不处理，PDF 无文字页面可交给识图。程序不执行附件，不自动下载远端链接。

NTQQ 收集消息的附件元信息（名称、类型、本地路径、来源 MD5），并补入全文索引遗漏的附件消息。读取本地源文件前验证消息范围、来源哈希和大小，拒绝网络路径、链接及来源不明的同名文件。图片路径缺失时，仅从当前 QQ 账号标准 `nt_qq/nt_data/Pic/YYYY-MM/Ori/MD5.ext` 原图目录核实，不用缩略图冒充原图。自定义 QQ 缓存位置需消息提供有效本地路径。源附件需已在 QQ 下载；缺失、超限或不支持的格式保持可见，并可在群详情重读。

每批最多处理 20 个附件，单附件最多 16 MiB、正文 12000 字，PDF 最多读取 10 页；图片单边最多 8192 像素。超限/截断明确标注。成功结果按原消息、来源哈希和解析版本缓存，关闭开关后不再用于新摘要及问答。解析失败不阻止正常聊天摘要。群详情列表与手动重读覆盖最近 200 条附件消息，最多显示 100 个；手动重读可补齐该范围内已下载的旧附件。

群详情提供读取状态和重读入口，查看读取结果时显示关联原消息、附件名、成功/等待下载/读取失败/内容截断等状态。不把路径或文件内容放入日志。普通回归和浏览器验收只使用合成文件与模拟 AI，不替用户启用任何真实群、不实际发送聊天附件。

权威 API 依据：[Vision](https://api-docs.deepseek.com/guides/vision/)。Files API 当前只支持图片，文档须先在本地提取或渲染后处理，不能假设接受 PDF/Office 文件。
