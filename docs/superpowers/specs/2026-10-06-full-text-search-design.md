# P2-01 中文消息全文检索

用户要求继续按路线图实施。P0/P1 已完成，本次推进 P2-01；保留上次摘要显示修复，不发布安装包或调用真实 AI。

## 行为

查找页增加发送人 QQ 号和消息类型（文字、链接、文件、回复、转发、系统、未知），与群、日期和关键词组合。消息专属条件仅在聊天消息模式生效，其他类型清空提交条件，避免摘要、知识结果看似经过发送人筛选。筛选范围写进结果说明和 URL，分页使用已提交条件，刷新恢复。

## 索引

新模块 `message_search.py` 使用 SQLite FTS5 内容为空的索引，按相邻两个字符编码为安全 ASCII token。适合两个及以上中文字符，不依赖中文分词词典；保留 LIKE 字面子串校验，避免只包含离散片段的误命中。ASCII 大小写与原 SQLite LIKE 一致，百分号、下划线、引号按字面查询。

归档初始化在独立事务中创建表、触发器、版本标记并一次回填已有消息。插入、修改、删除通过 SQLite 原生函数和触发器同步，回滚时一起回滚；无需注册仅新版支持的 SQL 自定义函数，保持已有版本写入兼容性。不改原消息、主键、同步游标及阅读状态。索引被备份与恢复一并保存，缺失索引会重建。缺少 FTS5 的运行环境降级原查询，其他建索引错误应报告而不是吞掉。

## 边界与验证

两个中文字符、英文混排、标点、重复词、特殊字符、表情、不连续片段；发送人/类型/群/当地日期边界；导入重复、更新、删除、回滚、旧库回填、关闭重开、数据库备份恢复；全量回归；大量合成历史消息下与原 LIKE 核对结果及耗时、查询计划。页面按 1280 和 390 宽度验收，使用合成数据，不读取用户聊天。

摘要和知识继续沿用现有搜索方式；本项不包含附件正文提取、自然语言问答或安装包发布。索引为可再生数据，首次打开大归档会花时间并增加磁盘占用。
