# 后台摘要期间的按钮操作

## 本次证据与根因

实际桌面后端为上一轮 `2026-10-22-action-recovery`。正常数据副本连续隐藏八次成功，346 条原始记录的隐藏偏好身份与详情身份一致；未发现偏好键漂移。

生产后台正在生成日报。对已隐藏商品进行幂等重复保存（不增加新隐藏）返回 HTTP 409“有任务正在运行”。原因是二手偏好共用群配置的全局排他任务锁，整个 AI 摘要任务期间都拒绝用户偏好写入。上一轮仅修复了列表刷新失败后的前端恢复，未涵盖这个运行环境因素。

## 处理

- 二手的收藏、隐藏、恢复和屏蔽名单操作复用已有短时 `bookmark_mutation` 类别；与 `daily` 和 `manual_summary` 双向兼容，同类偏好写入仍互斥。
- 存储活动租约使用同一协调器的身份令牌跨线程共享，并按引用计数保留至最后一次退出。不同协调器、默认直接租约和其他进程不获得共享权限。
- 备份、存储迁移、版本切换、采集、同步、问答等互斥关系保留；日报和手动摘要使用独立数据库连接，偏好不会提交或回滚摘要连接中的事务。
- 409 拒绝响应增加当前视野可见的 toast，保留各页面错误说明。需要等待的按钮不会表现为无反馈。

## 验证

- 跨线程、真实根路径下的协调器和 TestClient API 测试；日报及手动摘要期间隐藏、刷新确认、收藏、恢复、屏蔽、解除屏蔽均可成功。
- 不同协调器无法加入租约；备份、迁移、版本切换、采集、同步和问答仍排斥偏好操作。现有租约外部进程及跨线程拒绝／释放回归保持通过。
- 独立复查额外验证反向进入、外层先退出、子进程仍被阻止直到最终租约退出；80 项相关测试通过。
- 独立 Chromium 实际按钮测试：另一线程持有日报任务锁时，连续隐藏五个商品且每次刷新后仍隐藏、四次收藏切换、恢复显示正常；另跑上一轮完整故障恢复流程与相关页面导航。
