# P1-03 话题持续跟踪设计草案

日期：2026-10-05
状态：用户已于本次会话批准推荐方案；实施中，路线图完成状态以最终验证为准。

## 目标与范围

关联已生成日报及范围摘要中跨天、跨群的同一话题，集中展示讨论进展、最新有来源的结论和仍待解决的问题。允许用户纠正自动关联，纠正结果在刷新、重新生成和重启后保留。

在已有摘要上建立持续话题视图，不重写历史报告正文。原始消息、报告阅读、待办和知识库继续各自保存；不把不同群中相同消息 ID 当成同一来源。

## 方案比较

1. **推荐：本地保守关联与人工纠正。** 重用已生成摘要，无额外 AI 请求和外部服务。标题规范化后精确相同、且非泛化短标题的条目可自动关联；相似标题显示建议，由用户确认。可解释、容易回退，但无法自动理解所有同义改写。
2. **AI 语义关联。** 每轮比较历史话题与新增摘要，由模型输出关联建议。对同义改写更好，但增加费用、等待、隐私边界及错误关联风险，需要额外的提示词与证据验证。
3. **完全手动关联。** 用户创建话题并选择相关讨论。准确性由用户掌握，但无法主动减少跨天重复事项的整理负担。

本次选择方案 1。不得声称规则关联等同于语义理解；低置信度内容保留独立条目，不静默合并。

## 用户流程

- 摘要的“更多工具”增加“话题跟踪”，保留摘要、查找、群聊、设置四个主入口。
- 话题页打开时对本地已生成摘要进行更新，用户也可手动刷新。展示更新进度或等待状态、处理数量及无法读取的报告数量；刷新失败保留先前索引。
- 列表显示话题名称、涉及群、首次/最近讨论日期、讨论次数、最近进展、跟踪状态。支持群、日期、关键词和状态组合筛选，以及分页。
- 详情按时间显示讨论记录，注明报告范围、群、来源是否可核实、当前或旧版本。可打开对应报告与经过校验的原消息及连续上下文。
- 支持改名、归档/重新跟踪、把某条讨论关联到另一话题或拆成新话题、合并两个话题。纠正操作显示影响内容并要求提交当前修订号；不一致返回冲突提示，保留输入。
- 最新结论和未解决问题仅从能关联到该话题的报告条目提取：与话题共享经校验的消息引用才自动归属。无法明确关联的整份报告结论不得全部塞入每个话题。
- 未解决问题是“最近记录的问题”，不自动推断它已解决；详情保留时间和来源。没有有效结论时明确提示暂无可核实结论。

## 关联与持久化

- 标题使用 Unicode NFKC、大小写、空白和标点规范化。过短或“日常讨论”等泛化标题不自动跨报告关联。不同具体项目、版本和故障对象保持独立。
- 自动关联只使用确定的规范化标题；本地标题相似度用于建议，显示“待确认”。同日多群讨论可归到同一话题，时间线保留每个来源，不把不同群的内容去重丢弃。
- 讨论记录使用报告类型、报告编号、原话题标题、引用及重复出现序号生成稳定身份；文本变更和顺序变化不得把人工意见转移到无关话题。
- 每条记录保存当前报告版本或内容指纹、原标题、摘要、已校验的消息引用、所属话题、关联方式和人工修订。用户拆分的记录不在刷新时被自动重新合并。
- 报告重新生成后，未变条目沿用人工关联；已消失或实质变更的旧条目标记为旧版，不参与最新结论。历史意见仍可查看，新条目重新匹配。
- SQLite 新增话题、讨论记录和人工关联记录/修订信息。迁移可重复执行，旧库无需手动操作。话题名称可重名，人工拆分不能被唯一标题约束阻止。
- 删除群时级联删除该群讨论记录；跨群话题保留其他群记录，空话题不出现在默认列表。备份和恢复包含新增表；没有新的绝对文件路径需要迁移。

## 模块与接口边界

- `qq_digest/topic_tracking.py`：标题处理、报告同步、关联建议、分页查询、时间线和纠正服务。
- `qq_digest/web/topic_routes.py`：鉴权、请求验证、冲突状态、服务调用与页面接入。
- 独立话题模板及交互模板，复用现有页面样式和原消息连续浏览组件；用户内容用安全文本节点呈现。
- `web/app.py` 仅组装新路由，不继续集中添加业务逻辑。
- 设置增加独立功能开关 `topics`。已有“精简界面”预设保持关闭，新功能可在设置开启；关闭隐藏入口并禁止新接口操作，保留全部内容和纠正信息。
- 本地刷新及纠正使用任务互斥，与生成、群删除和存储迁移避免交叉修改。读取接口不在后台偷偷调用 AI。
- 更新操作使用 POST，读取使用 GET。刷新必须可重入、幂等；局部报告损坏单独提示，不清空其他话题。

## 错误与兼容边界

- 旧报告没有逐条引用时可显示其话题并明确“来源未记录”，不生成猜测引用。来源按钮继续通过报告类型、版本、群及日期校验。
- 无报告显示引导生成摘要；无话题说明该摘要未提取主要话题；文件损坏显示数量和报告链接。
- 更新过程中禁用重复提交；关闭面板或切换话题使过期响应失效。失败保留用户编辑内容，允许重试。
- 群删除、报告改版、无效日期、分页越界、多个标签页同时修改均有明确结果。

## 验收与验证

1. 连续三天同一话题、两个群的同一话题形成持续时间线；不同对象不因泛化标题被合并。
2. 用户纠正、合并、拆分、归档后刷新、重启仍保留；重复刷新不增加重复记录。
3. 重新生成改变标题/顺序/来源时，不把人工关联套到错误条目；旧版记录不成为最新结论。
4. 结论和问题按有效共享来源归属，原消息按钮可打开同群有效引用及上下文；旧报告不声称可溯源。
5. 未登录、关闭功能、并发冲突、输入越界和不存在目标返回正确状态；失败不丢弃已保存内容。
6. 旧库迁移、删除一个群后的跨群话题、备份恢复、存储切换和版本开关可回归验证。
7. Python 服务/接口测试、JavaScript 延迟响应和重复提交检查、真实浏览器宽窄屏交互全部通过后再标路线图完成。
8. 若打包发布，核对新增模板与模块；实际 EXE 启动未验证时单独注明，不把打包成功视作启动成功。

## 开发前检查

本次项目检查先运行现有全量测试和静态解析，并独立复审数据及网页边界。经确认的高优先级基础问题应先补回归测试修复，避免话题时间线建立在漏采或不一致的来源上。
